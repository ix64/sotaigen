# 头部与面部

## 现状

中性头由函数生成，有颅骨、前脸和下颌。皮肤里没有鼻子和五官，它们和耳、头发一起是单独节点的部件，由 `sotaigen/output/face.py` 生成（见“部件”）。头部 3313 个顶点（46 排，每排 72 个，加头顶 1 个），3420 个面，整个网格 12676 个顶点，头在源网格之后、加的环之前（[坐标与拓扑](../reference/coordinates-topology.md)）。转头、点头时，t < 0.9（t 是从头顶往下的头高比例）的皮肤只用 `head` 和 `jaw`，两者之和是 1，转头、点头时它们一起走；颈部的过渡按皮肤上的毫米平滑，沿整段颈分布（[绑定](../systems/rig.md#颈部的权重按毫米平滑)）。张嘴由 `jaw` 完成，视线由 `leftEye`、`rightEye` 完成（[下颌和眼骨](../systems/rig.md#下颌和眼骨)）。

**还没解决：** 下文“已知缺陷”里的侧面小转折、张嘴和视线的局限、UV 拉伸余量小，以及换头工具只走过自造的测试头。当前身体的 UV 拉伸余量需复测。

**形体（`sotaigen/form/head.py` 的 `_head_masses`）：** 颅骨的底部高于下巴，略悬在后颈之后；前脸在颅骨前方，鼻子以下向后收，所以侧面读得出朝向；下颌是一整块前低后高的体块（前端下倾 36°），下缘从下巴升到耳下，宽度由 `jaw` 决定；下巴是下颌上的一个小圆点，是头的最低点，中心在 0.56 d 和“颈前缘 + 0.125 头高”中靠前的那个，所以细长的头或粗的颈不会让下巴落到颈上。

**颈：** `sotaigen/form/anatomy.py` 的 `NECK_TOP = 1.5` 只加宽颈部圆锥的上端，下端和斜方肌相接处不变。颈和斜方肌并入躯干的圆角宽 0.10 T·`softness`，颈细时收窄到至多 1.5 倍颈半径（`NECK_BLEND_RADII`）。固定的圆角在细颈上把颈从肩一直撑到下巴，下巴下量到的大半是圆角，颈半径到求解下限也量不到细的颈围。颈半径 0.0667 T 以上的身体（女性、男性的 Q版和小巧）不受影响，更细的典型身体颈根的圆角收窄、上颈略粗，以保持颈围，头的形状不变。细颈的看图和数据见[细颈规则与依据](../systems/params.md#规格上的规则)。

**锁骨内端随圆角后退：** 锁骨内端（`clavicle_masses` 的起点，胸骨上切迹两侧，裆上 0.99 T，前后位置跟胸厚走）在圆角收窄后会露出来，悬在胸顶前方，只靠自己的窄融合（`(0.012 + 0.08·definition) T`）接着，截面上是一个下方内凹的小鼓包，比模板的排距还小，贴合跨不过去就翻转（压力测试的身体见[预设](../systems/presets.md#测试身体)）。所以内端向后挪圆角少掉的宽度的一半（`CLAVICLE_SINK = 0.5`），颈半径 0.0667 T 以上不动。只改这个点：锁骨的融合宽度、颈和斜方肌的圆角都没变，所以下巴下的颈围不变（[细颈规则与依据](../systems/params.md#规格上的规则)）。

**颈头交界：** 皮肤是头和身体曲面的平滑融合，喉部窄（0.08 头高）、后颈宽（0.16 头高），和身体其他关节同一个办法。

**颈环的位置：** `head_field` 返回的是一个平面，不是头：下巴下方 0.07 头高，向后每毫米升 0.32 mm。`wrap.correspondences` 和 `seat_neck_ring` 都读它，所以颈环的地标和抬升都由它决定。这个平面和模板颈环原有的斜度相近，抬升均匀，颈部不折叠；接缝落在融合之下的平直颈部。

**网格：** 从中心向外投射光线找皮肤，每列曲线按弧长分排，脸部（t ≥ 0.52）密度是颅骨的 2.2 倍，列向前脸聚拢（前方间距是均匀分布的 0.6 倍）。

**指标：** 全身静止尖锐折痕（法线夹角超过 90°）都在手和脚趾，头颈区没有超过 60° 的折角；转头、点头没有塌陷面。

**比例：** 颈宽、后脑相对中轴的后伸、下巴比前脸最前端的后收按动画风格取，不是写实头骨的。这些比例的观感需在当前身体上复核。

## 已知缺陷

| 名称 | 问题 | 影响 |
|---|---|---|
| 颈头过渡 | 带脸和头发后，正面、三分之四和背面都读得出是动画风格的头。侧面从鼻子到下巴是向后收的斜线。还剩三点：下颌下缘仍是一段短的平台，到喉部折成接近直角（短头身的身体最长）；长头身的身体下巴像一个小鼓包，三分之四在它上方有一个小转折；颈粗时下巴被“离颈前缘 0.125 头高”顶在前面，后收最小 | 需结合头颈比例和当前身体的侧面、三分之四视图评估 |

**张嘴和视线的局限：**

- 皮肤不开口，大张嘴时表现为下半张脸拉长，圆润身体还需检查下巴两侧的转折。
- 鼻和耳绑 `head`，会相对张嘴时的皮肤滑动；发束和脸颊的穿插仍需检查。
- 占位嘴可能被皮肤遮挡；虹膜随眼骨转动，没有眼睑配合，上下看时也可能被皮肤遮挡。
- 这些占位部件的产品分工见下文[部件](#部件)，需要口腔的下游走换头接口。

**颈部明暗线的小台阶。** 侧面、头发下方有一处转折，改下颌和平滑头部法线后仍可见。同一相机和光线下比较颈部网格与体块场：两者都有缓弯，局部向前的小折返主要出现在网格上。[逐行实测与范围](../systems/form.md#已知缺陷)

**其他看图看到的：** `crouch` 背面左下有一小块阴影岛。点头时后颈在灰模上有皱褶，转头时短头身的身体侧面颈上有一条细线。都没有塌陷面。

**`head_field` 名不副实：** 它是贴合用的颈环平面，头的形状在 `_head_solid`。因为 `wrap.py` 调用它，所以没有改名。

**UV 拉伸待复测：** `tests/test_uv.py` 的各向异性 p95 上限是 2.2；后脑下部和下颌下方是需要重点检查的区域。用 `scripts/uv_check.py` 在当前身体上读取分区结果。上游形体变化后需重新检查。

**交界折叠：** 颈环抬升不均匀时，按最近的环顶点复制抬升量会让相邻排互相穿过，最短的颈上先出现折叠。所以抬完颈环后整段颈按列重新等距（[贴合](../systems/wrap-uv.md#颈部的排)），不复制抬升量。`tests/test_head.py` 对全部身体把关：不折叠，颈部的面不压成线。

## 赛璐璐明暗线

**S 形台阶和碎阴影来自真实形体，不是网格：** 在隐式曲面上直接算同样出现。下颌、颊和后颈融合都是真实起伏，硬阈值会把它们画出来，所以整个头的皮肤用平滑法线（`sotaigen.output.face.head_normals`）。

**做法：**

- **从哪里来：** 只含颅骨和前脸体块的场的梯度。只换脸部解决不了后颈的碎阴影，所以要换整个头。
- **和颈的过渡：** 每一列从紧贴颈环的第一排往上，0.14 头高内从网格自己的法线渐变过去。第一排就是自己的法线，所以和模板颈部之间没有跳变。下巴下方转得急，只在下巴下方看得到相邻顶点的法线差。
- **下半张脸的阴影：** 平滑法线在下半张脸朝下，光从上方时鼻子以下全落在阴影里。所以脸的前方（`y` < 0，0.20 头高内渐变）从 t = 0.42 到 0.64 逐渐去掉 90% 的上下转向，左右转向保留。结果是静止时脸整块是亮的，阴影只从远侧绕过来；下巴下方在颈上的明暗边读起来像下颌投影。点头 30° 时脸的法线刚好接近阈值，正面是半张脸的一条边，不再有横穿脸的色带。这里的取舍是看静止、转头、点头定的，其他光向没有看。
- **导出：** 函数从 `skin_normals` 开始混合，返回全身的 `len(rig.verts)`×3。身体其余部分就是 `skin_normals`。`uv run sotaigen-dev export` 默认带上它和部件，`--no-parts` 导出纯身体。

**外壳描边沿文件里的法线外推：** three.js 页面的外壳和 MToon 都这样做。这是头发不能用球形法线的原因：外壳的下表面会穿过发束的上表面，页面的赛璐璐上出现大块墨色。所以头发用自己的网格法线，每束有自己的明暗，背面的阴影边因此有小锯齿。头发和皮肤的这条约束今后也成立。

## 部件

**定位（见 [DECISIONS](../DECISIONS.md#头部)的“分工”）：** 五官、耳、头发的形状和它们的表情只作占位，用来看图和走通导出路径，不再细化，不进对外约定。下游按角色重做脸和发型，走换头接口。形体和形体的动作照常做：头形、颈部、头颈交界、转头和点头，还有 `jaw` 骨和眼骨。皮肤不开嘴，要口腔的下游换整个头（见本页[张嘴的局限](#已知缺陷)）。

`sotaigen/output/face.py`（不能被 `sotaigen.pipeline` 导入，不算贴合的输入）的 `face_parts(name)` 和 `head_normals(name)`，默认导出已接上。函数接身体名，不是 `rig`，因为头的形状要从参数算，`rig` 里没有。

| 部件 | 顶点 | 外推 | 变形目标 | 描边 |
|---|---|---|---|---|
| `eyeWhite` | 150 | 0.25 mm | `blink`、`happy` | 否 |
| `iris` | 146 | 眼骨的球上（0.40 mm 处贴着皮肤） | `blink`、`happy` | 否 |
| `pupil` | 146 | 球外 0.10 mm | 同上 | 否 |
| `eyeLight` | 146 | 球外 0.20 mm | 同上 | 否 |
| `lash` | 60 | 0.70 mm | `blink`、`happy` | 否 |
| `brow` | 60 | 0.40 mm | `happy` | 否 |
| `mouth` | 45 | 0.30 mm | `happy`、`aa` | 否 |
| `nose` | 90 | 边缘压进皮肤 0.8 mm，最高 0.026 头高 | 无 | 是 |
| `ears` | 228 | 根部在皮肤内 | 无 | 是 |
| `hair` | 2614 | 见下 | 无 | 是 |

共 3685 个顶点，所有身体顶点数、顺序和面相同。不进 `wrapped.npy`，不改皮肤的拓扑和 UV。鼻和耳的颜色是导出皮肤的材质颜色。

**脸部坐标：** `(u, t)`，`u = x / 头高 / (headWidthRatio / 0.80)`，`t = (头顶 Z - z) / 头高`。除以宽度比，五官在不同头身上占脸宽的份额才相同。曲线沿视线投到皮肤，再沿皮肤法线外推到自己的层。

| 挂点 | 位置 |
|---|---|
| 眼 | `u = ±0.175, t = 0.605`，半宽 0.072 |
| 眉 | `u = ±0.096…0.26, t ≈ 0.49` |
| 鼻 | 中线，`t = 0.650–0.742`，最高点约 0.725 |
| 嘴 | 中线，`t = 0.828`，`aa` 最低到 0.868 |
| 耳根 | `t = 0.52–0.70`，`y = 0.03 头高`，`x` 从皮肤表面测 |
| 发际线（前额中线） | `t = 0.30`，到耳前约 0.50 |
| 发际线（后方） | `t = 0.84` |

**绑定：** 嘴的下排全在 `jaw`、上排 0.45、嘴角 0.5（`sotaigen.output.face.mouth_weights`）；虹膜、瞳孔、高光左右分别全在 `leftEye`、`rightEye`；其余全在 `head`。这些权重在 `sotaigen.output.face.bound_parts` 里按绑定加上，`head_parts` 本身不看绑定。眉、眼白、睫毛、鼻、耳所在的皮肤（嘴线以上）只有 `head`，所以它们不相对皮肤滑动。发束垂到 t ≈ 1.0，点头时随头摆，最多压进颈部不到 2 mm（测试把关）。碰撞球没有做，弹簧骨也没有做。

**表情：**

- 名字用 VRM 预设名。只给会动的部件，中性是全部权重为 0。
- 虹膜、瞳孔、高光闭眼时回到皮肤上、睫毛之下，所以跟着合上。视线不是表情，由眼骨转动：穿着者左是 Z+，没有在 VRM 运行时里验证方向。
- `blink` 和 `happy` 同时为 1 时位移直接相加，眼睛会过头，要由上层避免。VRM 的 `overrideBlink` 正是做这个的，还没接。
- `aa` 只改变嘴部薄片。张嘴是 `jaw` 骨的事：转动加前滑，下半张脸的皮肤和嘴一起走，`aa` 只是在这上面改口型。卡片和取舍见[张嘴](../motion/jaw.toml)。口腔内部、牙齿和舌头仍无几何，单一元音也不足以复现连续语音。

**头发是占位：** 盖帽 + 7 束刘海 + 4 束耳前 + 10 束后面。不是发型设计，只是挡住后脑和后颈。盖帽离皮肤至少 1 mm，边缘翻到皮肤下 1 mm。背面的边缘在灰模上是一道台阶，在赛璐璐上看得见它和发束之间的色差。

**实际文件成本：** 部件的大小主要是头发，5 个表情只占很小一部分。各表情移动的顶点：

| 表情 | 移动的顶点 | 增加的字节 |
|---|---|---|
| `blink` | 636 | 9560 |
| `happy` | 729 | 11536 |
| `aa` | 45 | 896 |

**运行时（`pnpm run runtime-check female-balanced male-balanced`，不给身体就是全部身体）：** glTF Validator 不报错误，Chrome 里 three.js 对 NumPy，全部检查姿势，不带表情和混合表情，皮肤和部件的偏差都在 1 mm 的门槛之下，法线一致。页面的部件开关和表情滑块由这个检查驱动。没有在 VRM 运行时或 MToon 上跑过。层间距（0.25–0.7 mm）远处闪烁没有实测。

**第一人称：** 五官、耳、头发放单独的节点，标 `thirdPersonOnly`。皮肤可以留在同一个网格，按 `auto` 分开，但颈部权重扩散到了颈环以下，`auto` 会把带 `head` 权重的上颈一起隐藏。都没有在运行时验证。

**看图：**

```sh
uv run scripts/head_review.py [--only heads,bodies,faces,motion]
```

## 换头的接口

颈环和头部挂点是对外约定，字段和规则统一见[换头的接口](../reference/head-interface.md)，金样是 `tests/contracts/topology.json` 的头区块、颈环和头顶顶点。由 `sotaigen.output.glb.head_attachments` 写，`eyeLine`、`eyeX` 由 `sotaigen.output.head_interface.eye_place` 量，换头前后同一个函数。`jaw` 在环和颈段上逐点为 0 由 `tests/test_rig.py` 守着。

`eyeLine`、`eyeX` 不用本工具的脸部坐标：它要除以只有本工具知道的头宽参数，换来的头量不出。

## 换头工具

```sh
uv run sotaigen swap-head BODY.blend HEAD.blend OUT.blend \
    [--scale S] [--parts-only] [--keep-parts ears,nose] [--report FILE]
```

无头运行，文件里不嵌 Python。`BODY.blend` 是 `sotaigen blend` 或 `uv run sotaigen-dev blend` 写的文件（T 姿势等换过静止姿势的文件也走通过）。`OUT.blend` 旁边写 `OUT.json`（报告），同样的数字在 `rig["sotaigen"]["headSwap"]`，塌陷面进 `quality`。接缝不闭合、新头的面翻转、接缝折叠超过 90° 时不写文件，以 1 退出；没有 Blender 时以 3 退出。代码在 `sotaigen/output/head_swap.py`（读文件以外的全部计算）、`sotaigen/output/skin_transfer.py`（权重转移）和 `blender/src/sotaigen_blender/head_swap.py`（GPL，读和写 `.blend`）。

默认换颈环以上的整个头。`--parts-only` 保留本工具的头皮肤，只换五官和头发，部件要已经按这个头的位置做好（不缩放、不平移，除非给 `--scale`）。两种都删掉全部占位部件，`--keep-parts` 留下点名的。

### 头文件的约定

`HEAD.blend` 坐标系和身体相同：X 朝穿着者左，-Y 朝前，Z 朝上。物体的变换和缩放随意，工具按世界坐标读。只读视图层里的网格、骨架和空物体；曲线、毛发曲线不读，名字写进报告的 `ignored`。

| 东西 | 怎么认 | 没有时 |
|---|---|---|
| 头的皮肤 | 带顶点组 `headRegion` 的连通块，只查它，它的边界自相接触时拒绝，错误里写物体名；没有标记时取所有网格里有开口的最大连通块，边界自相接触的块（生成的头发常有）跳过，留作部件，`quality` 里写是哪些物体 | 拒绝 |
| 颈口 | 皮肤最低的那个开口，闭合的一圈，顶点数随意。其他开口（嘴、眼）留着，报告里说有几个 | 拒绝 |
| 挂点 | 骨架里叫 `jaw`、`leftEye`、`rightEye` 的骨的头，或同名的空物体。骨的长度也读，空物体的按缩放算 | 那根骨留在旧头的位置，写进 `quality` |
| 不连通的部分 | 皮肤所在网格里的其他连通块，和其他网格。带有骨名顶点组（`jaw`、`leftEye`、`rightEye`、`head`……）的连通块按组绑，归一化；一个组都没有的按权重转移绑。牙、舌、嘴绑 `jaw`，眼球绑眼骨，都靠这些组 | 没有组的牙、眼球只会跟最近的皮肤走，不会自己找到眼骨 |
| 皮肤上已有的权重 | 离接缝两倍融合高度以外原样保留，其余转移 | 全部转移 |
| 表情 | 皮肤的形状键加到 `body` 上，名字不变，值为 0，按缩放；部件的形状键留在部件上 | |
| 法线 | 皮肤的自定义法线保留，接缝处转到新算的（见下） | 用 Blender 自己的 |

皮肤的材质加到 `body` 的材质槽后面，UV 按活动的 UV 层写进 `UVMap`；其他 UV 层和颜色属性不带。部件的材质、UV、修改器、不是骨名的顶点组都留着。

### 做了什么

1. **对齐。** 只有均匀缩放和平移，不转。颈口的中心对到颈环的中心，颈口到头顶的高度等于身体的颈环到头顶的高度；`--scale` 直接给缩放。
2. **接缝。** 颈口转成和颈环同向。顶点数相等（36）时逐点焊到颈环上，序号取最近的转法；不等时按弧长拉链，一圈三角形，和本工具的头在第一排上的做法相同（`sotaigen.form.head.topology`）。颈环和颈以下的顶点不动。
3. **融合。** 新头的颈上，离接缝一段距离（`0.05–0.10 头高`，默认两倍颈口和颈环的平均距离，至少两排）以内的顶点重新解：最小化平方拉普拉斯，下面读颈的两排，上面读头的两排，所以两边的斜率都接上。邻点的权重按边长的倒数，短于颈环平均边长 0.1 倍的边按 0.1 倍算，所以颈口贴在颈环上、拉链带没有高度时也解得开，迭代三次。这段以外头的形状一点不动。量到的面对比新头自己的面翻转时拒绝，颈口离颈环远就说太远，贴在环上就让查头自己的颈有没有折叠，或者把颈口改成 36 个顶点逐点焊接。
4. **法线。** 同一个顶点只有一个法线，所以环上法线天然连续。为了不让明暗线停在折角上，环上用跨两边算的法线，新头从它转到自己的法线，转完的距离是融合高度；颈以下用 Blender 自己的。
5. **权重。** 见下。
6. **骨。** `jaw`、眼骨和它们的控制骨平移到挂点，长度换成头文件的，静止旋转不变，所以局部轴还是约定的那样（[下颌和眼骨](../systems/rig.md#下颌和眼骨)）。`jawGlide` 跟 `jaw` 的长度等比。`head` 骨不动：它的枢轴是颈的约定，骨尾只是显示。
7. **写回。** 在原来的网格上用 bmesh 删头、加头，形状键和它们的驱动器、顶点组、修改器都留着；颈以下的顶点序号不变，新头排在最后。`headRegion`、`head`（`region`、`neckRing`、`crownVertex`，`eyeLine` 和 `eyeX` 按新骨和新头的头顶、颈环重算，和换头前同一个函数）一起更新。
8. **检查。** 写完先用出厂设置重开，读回接缝的闭合、折角和法线，按控制骨摆 `headTurn`、`headNod`、`jawOpen`、`jawTurn`、`jawNod`、`gaze`，数塌陷面。通过才移到 `OUT.blend`。头颈配比的规则不查，[按决定](../DECISIONS.md#头部)由这一步代替。

### 权重转移

`sotaigen/output/skin_transfer.py` 的 `transfer_weights(源顶点, 源面, 源权重, 目标顶点, 目标面, fixed=, distance=)` 不知道什么是头，衣物适配也用它。做法是 [Abdrashitov 等 2023](https://doi.org/10.1145/3610543.3626180)：目标顶点离源足够近（对角线的 5%）、法线夹角在 30° 内的，直接取最近点的权重；其余顶点解 `Q = -L + L M⁻¹ L`，已信任的固定；最后对解出来的和它们附近的顶点平滑 10 步，每个顶点留最大的 4 根骨，归一化。

只用 numpy 和 scipy，没有新依赖。读了[作者的示例](https://github.com/rin-23/RobustSkinWeightsTransferCode)（MIT，要 libigl）和 [Robust Weight Transfer](https://github.com/sentfromspacevr/robust-weight-transfer)（GPL-3.0，要 libigl 和 robust-laplacian）的代码，论文本身没读。libigl 用到的三件都不长：最近点（`cKDTree` 筛候选，再逐三角形精确求），余切拉普拉斯，带约束的求解（`splu`）。这段要 scipy，Blender 里没有，所以放在 `sotaigen/` 而不是 `blender/`，按论文的公式和 MIT 的示例重写，是 Apache-2.0，没有用 GPL 插件的代码。和示例不同的三点：

- **翻转的法线（插件也有）：** 夹角按绝对值算，面朝里的壳照样算近。
- **不连通的部分（做法和插件不同）：** 插件用 robust-laplacian 的点云拉普拉斯把各块连起来。这里每个连通块至少信任一个顶点：一个都不够近的，取离源最近的那个。块上只有一个固定点时解出来就是常数，所以这样的块整块跟着最近的东西走，对牙、眼球、飘在外面的发束都是对的。代价是块内部不会有渐变。
- **坏三角形：** 拉普拉斯的边权下限大于零，代替 robust-laplacian 的本征三角化，能解，坏三角形上精度差一点。

换头时用两次：旧头和颈下三排到新皮肤（颈环的权重固定，所以 `jaw` 在环上仍是 0）；新皮肤和颈到没有顶点组的部件。

### 验证范围

`scripts/head_swap_study.py` 用 `blender/fixtures/made_up_head.py` 生成测试头，覆盖头形变化、不同颈口密度、牙舌、眼球、头发壳、独立骨架和物体变换。复现和出图：`uv run scripts/head_swap_study.py female-compact male-balanced female-chibi --coarse male-balanced`。

`tests/test_head_swap.py` 和 `tests/test_skin_transfer.py` 检查权重转移、颈以下皮肤与修正保持、接缝、骨骼与部件跟随，以及禁用自动运行脚本时的文件。自造测试头的覆盖不代表真实下游头已验证；接缝折角、法线和复合动作需按新头重新检查。

### 换头工具的已知缺陷

- 接缝可能出现颈前明暗线；粗头网格的第一排较远时，法线过渡也需检查。增加融合高度不能保证消除局部折角，过高还可能碰到下巴。

- 收窄下颌与短颈的组合在张嘴加转头、点头时可能折叠，单轴动作不足以覆盖。
- 张嘴的 `jaw` 权重取自我们的头，它没有嘴。头皮肤有真的口腔时，上下唇的分界不会落对位置，要在头文件里自己刷（离接缝远的会保留）。
- 手到头、手到脸的姿势资产是按旧头解的，换完没有重解，`quality` 里有一条。
- 对齐不转，头文件的朝向和颈的斜度要大致对。颈口离颈环太远时只会拒绝或得到喇叭口，不会自动缩放颈。
- 颈口对到颈环靠两者顶点的中心，所以颈口的顶点在环上分布不均时，中心不重合，形状再贴也会错开一点。
- 报告的 `gapMm` 是把颈口按等弧长取 36 个点、和颈环逐点比，颈环的顶点不均匀，所以量大了：颈口贴在环上时仍报约 6 mm。融合高度也按它算，所以这种头的融合比说的高一些。
- 换头应以新头上的动作检查为准，但生成身体的放行目前不完整： `sotaigen blend FILE OUT --for-head-swap` 只放开细端（颈围不到 0.47 头），质量提示里写一条；颈自己的下限和粗端（1.58）仍查。这种身体在我们自己的头上没有验证过，要换了头才算数。
- 只走过自己造的测试头，没有拿过下游的真头；`--parts-only` 只测了绑定和骨，没有看图。

## 下半张脸的检查

形体由 `sotaigen/form/head.py` 定义，见本页[现状](#现状)。`CHIN_CLEAR` 保持下巴中心在颈前缘之前，需结合粗颈、长头身比例检查；最低点不能落在喉部。`tests/test_head.py` 的 `test_the_side_view_shows_which_way_it_faces` 检查侧面朝向，另需检查下颌至喉部的转折、下巴鼓包及动作折叠。

形体调整后复核翻转、塌陷、折角与 UV；拓扑不变也不代表拉伸读数不变。

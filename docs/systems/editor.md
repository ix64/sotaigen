# 编辑器

## 现状

页面是一个 Vite + React + TypeScript 应用（UI 用 shadcn/ui，路由用 TanStack Router），由 `web/serve.mjs` 在一个端口上提供。`/` 是编辑器，地址记录 `body`、`pose`、`look`、`panel`、`inspect`，刷新和分享能回到同一处；滑块值不进地址，要留存用导出 JSON。

导出的检查页 `web/runtime/check.html`、`shot.html` 单独构建，不进路由，也不带这个应用。

**目录为什么分三块：** `web/runtime/` 是不依赖 React 的运行时（读 GLB、驱动辅助骨和修正形状、赛璐璐着色），编辑器、检查页和 Node 下的测试都用它，`tests/test_export.py` 拿它对照 Python；`web/editor/` 是编辑器自己的界面和状态；`web/src/` 是应用外壳、路由和 shadcn/ui 组件。三块是同一个包、同一份依赖，分开只是为了让运行时不沾界面。

**内部接口：** `web/serve.mjs` 的 HTTP 接口（`/api/body`、`/api/touch`、`/api/blend`、`/api/mend`、`/api/params/read`）和它与 Python 工作进程（`sotaigen_dev/editor/worker.py`）之间的协议属于编辑器内部接口，随前后端同步更新。说明写在两个文件的开头；测试的替身工作进程 `web/tests/standin-worker.mjs` 照它回答。对外的是文件：参数文件、GLB 和 `.blend`（[对外约定](../reference/README.md)）。

编辑器当前在松手后生成：滑块选参数，拖动时模型不动，松手后本地 Python 服务生成完整的 GLB，页面显示和导出的都是这一份。能切换预设、姿势和观感，能导入导出 JSON，机器上有 Blender 时能导出绑定好的 `.blend`（[导出 .blend](#导出-blend)）。

**还没解决：**

- 界面操作和快速调整的观感尚待维护者验收。
- 当前身体的生成耗时、滑块可用范围和无效参数比例需要复测：运行 `pnpm run editor-sweep`，并查看展开的状态或 `build/web/smoke.json`。
- 腋下的小步调参连续性尚待复核，见[流水线自己会跳](#流水线自己会跳)。

- 快速调整的增益是初值，没有逐个看图定。

```sh
pnpm install
pnpm run editor              # 构建页面并打开 http://127.0.0.1:8124/，要换端口写 pnpm run editor 8125
pnpm run editor-dev          # 改页面时用：同一个端口，Vite 在服务里面，带热更新

# 类型、构建和真实 Chrome 里的全部用例，约 1 分钟。失败的用例在 build/web/test-results/ 留下截图和 trace
pnpm run web-check
# 每个滑块的可用范围和两端的身体，写 build/reports/editor-sweep/。形体改了要重跑
pnpm run editor-sweep
# 不开页面，校验或导出一个参数文件
uv run sotaigen check FILE.json
uv run sotaigen glb FILE.json OUT.glb
```

页面不需要先跑 `uv run sotaigen-dev build` 或 `export`：预设也是按参数现生成的，第一次看要等，之后读缓存。改了 `sotaigen/`、`data/`、`template/` 要重启 `pnpm run editor`，运行中的工作进程还是旧代码。

| 文件 | 作用 |
|---|---|
| `sotaigen/generation.py` | 任意参数的 GLB 和 `.blend`，命令行和页面的工作进程都用它 |
| `sotaigen_dev/editor/worker.py` | 页面的本地工作进程 |
| `sotaigen/mend.py` | 被拒绝的身体退回哪项参数能修好，命令和工作进程共用（[哪项参数](export.md#哪项参数)） |
| `sotaigen_dev/editor/schema.py` | 从 `sotaigen/params/rules.py`、`sotaigen/params/spec.py` 生成前端规则和 JSON Schema，`web/serve.mjs` 启动时运行 |
| `sotaigen/params/file.py` | 读写参数文件 |
| `sotaigen/cli.py` | 命令行：校验参数文件，导出 GLB 和 `.blend`，换头 |
| `sotaigen/rig/touch.py` | 手到头、手到脸的触点，由工作进程按身体解，见[触点姿势](#触点姿势) |
| `sotaigen/data/sliders.json`、`sotaigen_dev/editor/sliders.py`、`web/editor/sliders.ts` | 滑块：定义只有 `sliders.json` 一份，`sliders.py` 和 `sliders.ts` 是同一套换算的两边实现。`groups` 决定界面的分组，`section` 是组内小标题的 id，`measure` 在滑块下放成品实测卡，`reading` 把数值换算成另一个毫米数。滑块的名称、两端、说明（数值的含义和单位，见 [PARAMETERS.md](../PARAMETERS.md)）在 `web/messages/`，见“界面语言” |
| `web/editor/params-file.ts` | 页面的参数文件读取和校验，不依赖浏览器 |
| `web/editor/rebuild.ts` | 什么时候发请求、谁的结果算数，不依赖浏览器 |
| `web/editor/store.ts` | 页面的状态和全部操作，包括撤销。React 只读它 |
| `web/editor/viewport.ts` | 三维视图：场景、相机、观感、点选部位。不懂参数 |
| `web/editor/looks.ts` | 观感：赛璐璐之外的剪影、雕塑、X 光，只换材质和叠加骨骼，不动几何 |
| `web/editor/limits.ts` | 滑块哪些区段会被规则拒绝，不依赖浏览器 |
| `web/editor/messages.ts` | 规则和生成器的英文原句对应哪条消息、哪个分组，不依赖浏览器，也不引用编译出的消息 |
| `web/editor/text.ts` | 页面取词：按 id 取滑块、分组、预设、姿势的名称，`say` 交给 `messages.ts` |
| `web/messages/en.json`、`zh.json`、`web/project.inlang/`、`web/scripts/paraglide.mjs` | 界面文案和它的编译配置，见“界面语言” |
| `web/editor/regions.ts` | 分组的层级和顺序、部位取景、骨骼到分组的对应。`sliders.json` 新加分组要同时加在这里和两份消息里，`ui.spec.ts` 检查每组都在左侧导航里 |
| `web/editor/EditorRoute.tsx`、`EditorPage.tsx`、`boot.ts`、`components/` | 页面 |
| `web/editor/components/TopBar.tsx`、`StartPicker.tsx` | 顶栏：起点、撤销、参数文件菜单、导出 |
| `web/editor/components/Inspector.tsx` | 显示面板 |
| `web/editor/sweep.mjs` | 滑块范围扫描，诊断工具。性别没有的参数（男性的胸形）不扫 |
| `web/tests/ui.spec.ts`、`smoke.spec.ts`、`fixtures.ts`、`standin-worker.mjs` | 真实 Chrome 里的用例，见“怎么测” |
| `web/serve.mjs` | 唯一的本地服务：页面、`build/`、工作进程、缓存 |
| `web/src/` | 应用入口、路由、主题和共用组件。`components/ui/` 是 shadcn 组件，有意改过的只有 `slider.tsx`；`popover.tsx`、`dropdown-menu.tsx` 是照 shadcn 手写的精简版，只留用到的部分 |

`params-file.ts`、`rebuild.ts`、`sliders.ts` 只用 Node 能直接剥离的类型语法（不用 `enum` 和参数属性），因为 `tests/test_editor.py` 用 `.node-version` 固定的 Node 直接运行它们，不装 npm 包。

`tests/test_editor.py` 在 Node 下对照 Python 考规则和滑块，用替身工作进程考取消和缓存，并逐字节核对工作进程的 GLB 和导出的一样。

JS 依赖只有一份，在 `web/package.json` 和 `pnpm-lock.yaml`，用 pnpm 管，直接依赖都固定版本，所有依赖都发布超过 14 天。不要用 `shadcn add` 的默认结果直接提交：它会加上未固定版本的 `cn` 包并把组件的 import 改过去，这里统一用 `web/src/lib/utils.ts`。

## 界面

界面按部位组织参数，并显示哪些值已改动：

- **按部位看，一次一组。** 左侧分“整体”（比例、快速调整）和“局部”（头部、颈部、肩胸、胸形、手臂、腰腹、胯、臀形、腿部，从上到下）。“整体”只放作用于全身的：比例是长度，快速调整是一次改写多项参数的宏滑块。躯干按部位拆开，每组有自己的取景：肩胸从正面，腰腹从侧面（前倾、后靠、腹前弧、后腰凹入只有侧面看得出），胯从前四分之三，臀形从背后。工具栏可以关掉跟随。点模型身上也能选分组，这时相机不动：肩和上背是肩胸，腰和后腰是腰腹，小腹前面是胯，后面是臀形。
- **拖之前就知道禁区。** 规则不允许的区段直接标在轨道上，会随别的滑块变化。
- **看得出改了什么。** 滑块的条从起点刻度画到当前值，改过的项有圆点和“恢复”按钮，随头身比变化的项标“联动”。分组旁有改动数，“已改动”列出全部。
- **精确和可退。** 数值可以直接输入，方向键微调。撤销和重做包括换预设和导入，回到见过的参数读缓存。
- **起点一目了然，又不占地方。** 顶栏写着当前起点（如“女性 · 修长”），点开先选模板，再选这个性别的典型身体，两个性别的组名相同（[名字](presets.md#名字)）。换模板时保留组，那个性别没有这组就取它的第一个典型身体。导入的文件选中它自己的模板，顶栏写“男性 · 导入的文件”；它记的来源是这个性别的典型身体时，换模板按那一组走，但不标为选中。它通常只选一次，所以不常驻在滑块上方。
- **文件归文件。** 顶栏的“参数文件”菜单导入、导出 JSON。导出 GLB 是主按钮，旁边的下拉里是“导出 .blend”和“带 IPC 接触导出”，它们的进度和结果写在视口上方状态行的下面。
- **看和改分开。** 左边改身体，要等生成，会写进文件。右边的“显示”（`I`）只改看的方式，立刻生效，不生成，不进文件：观感、表情（含 `jaw` 和眼骨的张嘴、视线滑块，叠在当前姿势上）、部件开关、辅助骨驱动、模型信息。换新身体时这些保持不变。底部工具栏只留常用的取景、姿势和对比。
- **名字不撞。** 姿势只指动作（底栏）；躯干的前倾、后靠是腰腹组的“侧面曲线”。风格只指预设；宏滑块叫“快速调整”。
- **状态不抢视图。** 平时只有一行状态，生成时有按上次耗时估算的进度条，问题列表有内容才出现，耗时点开才看。问题写成中文，能对应到分组的带“去调整”。
- **观感优先。** 深色主题下视口是中灰，不是深色：赛璐璐的描边接近黑色，放在深色背景上就看不见了。

快捷键：`1`–`4` 转视角，按住 `C` 看调整前，`I` 开关显示面板，`⌘Z` 和 `⇧⌘Z` 撤销和重做。

**当前采用完整生成。** 预计算变形基需随形体实现变化重新生成，近似预览还需核对与成品的差异，因此当前页面未采用这两种方案。松手后生成同一份显示与导出结果，速度要求见[架构](../ARCHITECTURE.md#1-目标与边界)。

## 界面语言

页面有英文和中文两种界面语言，用 [Paraglide JS](https://inlang.com/m/gerre34r/library-inlang-paraglideJs) 加 inlang 的消息格式。

- **文案在 `web/messages/<语言>.json`**，扁平的键，按区域加前缀（`top_`、`status_`、`slider_`、`rule_`……）。编译器把它们编成带类型的函数，生成到 `web/src/paraglide/`，不进 git。编译配置只有 `web/scripts/paraglide.mjs` 一处，Vite 插件和 `pnpm run typecheck` 都读它。`@inlang/paraglide-js` 和 `@inlang/plugin-message-format` 是构建期依赖，运行时只有生成的代码；消息格式插件按 npm 依赖装，`settings.json` 用本地路径引用，编译不联网。
- **英文是源语言和回退。** 项目要开源，英文对外部贡献者没有门槛；第三种语言漏翻时退回英文也仍然可读。语言的取法是“页面上选过的（只存在这个浏览器里）→ 浏览器语言 → 英文”。语言在顶栏的语言菜单里选，每种语言用它自己的名字，切换时整页重载。`<html lang>` 跟着界面语言走。
- **只翻页面自己说的话。** 规则、生成器、文件读取报的英文原句不变（`tests/test_editor.py` 拿它们对照 Python），`messages.ts` 只决定原句对应哪条消息；不认识的原句照原样显示。参数名、命令行示例、单位照原样显示。诊断工具 `sweep.mjs` 的报告仍是中文，直接读 `zh.json`。
- **滑块的词也在消息里。** 名称 `slider_<name>`、两端 `_low`/`_high`、说明 `_help`、读数前缀 `_reading`，分组 `group_<id>`，小标题 `section_<id>`。`sliders.json` 只留结构和数值；新加滑块要在两份消息里各加这几条，`test_every_slider_says_what_it_means` 会检查。
- **Node 下跑的文件不引用编译出的消息。** `messages.ts`、`sliders.ts` 要能被不装 npm 包的 Node 直接运行，所以由调用方传入 `say`：页面传 `text.ts` 的，测试传一个读 `zh.json` 的。
- **复数用消息的变体**，一个变体只放一个选择器。中文的变体只有 `other`。
- **中文文案沿用原来的句子**，英文按同样的意思写成平实的英语，不逐字对应。英文通常更长，左侧分组栏和工具栏以英文为准检查不截断。

## 怎么测

| 层 | 在哪 | 测什么 | 代价 |
|---|---|---|---|
| 逻辑 | `tests/test_editor.py`，属于 `uv run sotaigen-dev test` | 规则、滑块、禁区、提示语，在 Node 下对照 Python；取消和缓存 | 秒级，不要浏览器和 npm 包 |
| 文案 | `tests/test_editor.py`，属于 `uv run sotaigen-dev test` | 两份消息的键和参数一致，页面按 id 取的词都有，页面代码里没有不经消息表的文字 | 秒级 |
| 文案 | `web/tests/messages.test.mjs`，`pnpm run web-check` | 编译出的每条消息在两种语言、单数和复数下都渲染得出，不退回键名 | 秒级，要先构建 |
| 界面 | `web/tests/ui.spec.ts`，`pnpm run web-check` | 页面的行为，每个用例有自己的服务。浏览器语言设为 `zh-CN`，用例读中文；英文页面有自己的用例 | 约 60 秒。工作进程是替身，一律回同一个真实 GLB |
| 冒烟 | `web/tests/smoke.spec.ts`，`pnpm run web-check` | 真实工作进程：预设和 `uv run sotaigen-dev export` 逐字节相同、校验器通过、崩溃恢复、页面导出的 `.blend` 能被 Blender 打开。耗时写 `build/web/smoke.json` | 约 2.5 分钟 |

替身发现不了真实流水线的问题，所以冒烟不能省。界面用例尽量按角色和可见文字定位，只有取消、计时这类界面上看不到的才读 `window.editor`。

## 等待

| 情况 | 页面的表现 |
|---|---|
| 拖动中 | 模型不动，不发请求，写“调整中”。规则不通过时立刻列出原因 |
| 刚松手 | 立刻写“生成中”和已等秒数，旧模型留着 |
| 松手后 0.6 s 内按下下一个滑块 | 这次不发请求，所以可以连着调几个滑块，只算一次 |
| 生成中又动了滑块 | 第一下移动就取消，见下 |
| 回到见过的参数 | 不等 0.6 s，直接读缓存。回到屏幕上那一个，什么也不做 |
| 换预设、重置、导入 | 不等 0.6 s |
| 规则不通过 | 不发请求，继续显示上一个有效模型，列出原因，不能导出 GLB，能导出 JSON |
| 接缝规则预警 | 照常生成，黄色提示 |
| 规则通过但结果有质量问题 | 换成结果，红字列出哪一条，写“已生成，但有检查未通过”，照常能导出，问题写进文件（[导出分级](export.md#导出分级)） |
| 规则通过但网格损坏：翻转、越中线、皮肤不闭合 | 仍然换成结果，要能看到坏在哪里，写“已生成，但网格损坏，不能导出”，问题列表写坏在哪些部位，“去调整”到最多的那个组。只有导出这一步拒绝，见下面三行 |
| 网格损坏时点“导出 GLB” | 不保存，状态行下面红字说“拒绝导出 GLB，网格损坏：”加逐条原因，点叉关掉。按钮不禁用：点击是在问这一个身体，等生成完才知道答案，下一次点击重新判断 |
| 生成失败、工作进程死掉 | 写“生成失败”和原因，旧模型留着。动一下滑块或点导出 GLB 会再试 |
| 启动不了 Python | 写“生成服务不可用”和要运行的命令 |
| 不是由这个服务打开 | 整页写要运行 `pnpm run editor` |
| 点导出 GLB 时还在生成 | 等到它，再保存最新的那一个 |
| 点“带 IPC 接触导出 GLB” | 用点击时的参数，在服务器上单独的工作进程里烘焙肩腋、腹股沟、垂臂三张接触表，状态行下面写正在烘哪张和已用时间，完成后保存 `<预设>-ipc.glb`。滑块照常可用，动滑块、离开页面都不会打断它，烘完的结果留在缓存里。同时只烘一个，再点一个不同的身体会取代前一个 |
| IPC 导出时某张表烘焙失败 | 照样保存，状态行下面红字说哪张表退回了雕塑修正，点叉关掉；这一条也写进文件 |
| IPC 导出时网格损坏 | 工作进程贴合、绑定之后就回答，不烘焙，不写文件。不保存，状态行下面红字说“拒绝 IPC 导出，网格损坏：”加逐条原因 |
| 三种导出之一因网格损坏被拒绝 | 另有一条消息找能修好的参数（[哪项参数](export.md#哪项参数)）：写试到第几项和已用时间，在单独的工作进程里跑，滑块照常可用。找到后写退回哪项、从多少到多少，“去调整”到它的组；找不到就说修不好。同一份参数只找一次；点叉或动滑块换了参数就真取消。只有皮肤不闭合时不找 |
| 点“导出 .blend” | 用点击时的参数，在单独的工作进程里生成，状态行下面写“正在导出 .blend”和已用时间，完成后保存 `<预设>.blend`。滑块照常可用；生成期间菜单项禁用，再点不会启动第二个 |
| 没有 Blender | 菜单项一打开就是禁用的，下面写要装 Blender 或设 `BLENDER`、然后重启编辑器；GLB 不受影响 |
| `.blend` 拒绝导出或失败 | 网格损坏时和 GLB 一样拒绝。不保存，状态行下面红字说原因，点叉关掉，见[导出 .blend](#导出-blend) |

**取消是真取消：** 服务器按进程组杀掉工作进程，页面的请求也同时中止。结果不会靠晚到覆盖新的：页面只认最新一次请求的回答。

**服务仅允许本地访问：** 只回答 Host 是 `127.0.0.1`、`localhost` 或 `[::1]`（可带端口）的请求，别的一律 403，所以把域名指向回环地址的网站（DNS 重绑定）读不到 `build/`。POST 还要求没有 Origin 或 Origin 和 Host 同源：别的网页用 `text/plain` 发跨站 POST 不需要预检，不拦就能打断生成或发起几十分钟的 IPC 烘焙。不带 Origin 的脚本（`sweep.mjs` 这类）照常可用。路径解码失败回 400，文件在检查之后读不出来回 404，单个请求的其他错误回 500，都不会让服务退出；服务一退出，脱离进程组的 Python 工作进程就会留下来。`ui.spec.ts` 的 “the server” 一组考这些。

**缓存：** 在 `build/cache/editor/`，键是参数加“生成版本”的哈希。版本是 `sotaigen_dev/editor/worker.py` 能运行到的代码（`sources.code_key`，注释和用不到的定义不算），加 `data/`、`template/` 全部文件和 `uv.lock` 的摘要。它比绑定指纹范围大，因为 `face.py`、`export.py` 不在绑定指纹里。上限 64 个身体，超出时按最近使用淘汰，读取也算使用。可以随时删除。

`.blend` 有自己的缓存 `build/cache/editor/blend/`，见[导出 .blend](#导出-blend)。

**同一份参数和 `uv run sotaigen-dev export` 的 GLB 逐字节相同：** `tests/test_editor.py` 和 `web/tests/smoke.spec.ts` 都核对。`extras.sotaigen` 由 `sotaigen.output.metadata` 写，和别的入口一样（[GLB 约定](export.md#glb-约定)）；典型和测试身体的参数多一个 `name`，并量检查姿势。

**预览和导出是同一个文件，拒绝在页面上：** 工作进程对损坏的身体照样写 GLB，回答里 `broken` 列出 `sotaigen.output.quality.broken` 的诊断（没有问题时是空列表），`failures` 照旧；缓存连同回答一起留着，所以读缓存时同样拒绝。IPC 导出的文件只为保存，所以直接回答 `{"ok": false, "broken": [...]}`。服务不判断这一点，`/api/body/<键>.glb` 能取到预览，文件的 `extras.sotaigen.quality.found` 里有级别为 `broken` 的诊断。

**找参数不进缓存：** `POST /api/mend` 只回答 `{ok, mend}`，没有文件；工作进程沿途说 `{"stage": "3/35"}`，`GET /api/mend` 读进度。页面记着这一份参数的答案，服务不留。

### 耗时

**指标：** 松手后 10 秒内出造型，选定后 10 分钟内导出，见[速度指标](../ARCHITECTURE.md#1-目标与边界)。导出时可选的 IPC 不受这一条限制。一次生成超过 10 秒，展开的状态里会写“超过了 10 秒的速度指标”。

**测量方法：** 调参和默认导出都不烘焙接触表，默认带[隐式场垂臂修正](rig.md#垂臂的隐式场修正)。生成耗时以当前身体、锁定依赖和机器负载下的结果为准；同时记录工作进程各阶段耗时、松手后等待和页面载入时间。

求解在前，贴合和绑定在第二个进程里，头、部件、曲面检查和标定场（垂臂修正要读它）同时在主进程，最后导出。导出里的姿势修正分在两个进程（`sotaigen_dev.editor.worker.split_correctives`）：

1. 第二个进程算雕塑肩腋修正。主进程同时准备垂臂表，算腹股沟雕塑目标。
2. 两个进程各解半张垂臂表（前抬键隔一个分一个）和它们的法线目标，第二个进程先准备自己的垂臂表、最后算肩腋的法线目标，主进程还算腹股沟的法线目标。
3. 主进程合起来写 GLB。和 `Correctives.production` 在一个进程里算的结果逐字节相同，`tests/test_editor.py` 核对。

一个进程里串行算时（`uv run sotaigen-dev export` 就是这样），垂臂表和法线目标也依次计算。法线目标只蒙皮动到的三角形和它们的一圈邻居，`pose_skins` 记住骨骼的静止矩阵，结果和算全身逐位相同。参数求过的身体没有求解这一项。

IPC 导出按肩腋、腹股沟、垂臂的顺序烘焙，耗时取决于身体与缓存；尚未在编辑器里系统实测。读缓存的耗时也需与首次生成分开记录。

这里大多是持有 GIL 的小 NumPy 调用，因此并行使用进程。

**快的写法：** `rig.skeleton.diffuse` 按列用 `np.bincount`，不用 `np.add.at`，索引顺序不变，所以每个和的舍入也不变。`calibrated` 只记住解出的腰、胯偏移，不记住场，因为 `wrap_body` 会摘掉它拿到的场的裁剪。两者的结果都和原写法逐字节相同。

**GPU 的取舍：** 贴合包含许多小批量、同步的场求值，调度开销可能抵消 GPU 的优势；同时需维护另一份场实现，并验证精度和确定性。因此尚未采用 GPU。重新评估时应使用当前身体的真实批次，同时检查绑定与姿势结果，不能只比较简化场的速度。

姿势和观感切换不用请求。换模型时相机不动，所以能直接比较前后。

## 触点姿势

底栏姿势下拉的“手到头、脸”一组是[触点](touch.md)：头顶、额前、脸侧、嘴边、耳后，脸侧和耳后另有双手的。它们不在 GLB 的 `checkPoses` 里（决定是不进 GLB），由服务端按当前身体解，页面只拿到关节角，用和检查姿势相同的 `setPose` 摆，页面里没有第二份 IK。姿势名进地址，刷新回到同一个触点。

**接口：** `POST /api/touch` 收 `{ sex, body }`，解好了才回答，地址在 `touch` 字段，形如 `/api/touch/<键>.touch`，内容是 JSON：`poses`（姿势名到关节角）和 `reports`（每个姿势的 `reached`、到达误差、落在第几个位置、手上哪个点）。

**单独的工作进程：** 和 `.blend` 一样，第一次选触点姿势时才启动，不和滑块共用，所以调滑块不会打断造型。一个身体的全部触点一次解完，所以换触点不再等。页面每个身体只问一次，换身体（模型落地后）再问。

**缓存：** `build/cache/editor/touch/`，键和 GLB 相同，上限 64 个身体，每个几 KB。

**怎么显示：** 解的时候模型回到绑定姿势，不让手穿过下一个头，状态行下面写“正在按这个身体解触点姿势”。解完直接摆上，没有提示。够不到的姿势摆最接近的一次，状态行下面红字写“这个身体的手够不到这里”和差多少。

**耗时：** 从参数求解、贴合、绑定，再解五个触点；解的部分负载约 12 时 7–27 s（[验收](touch.md#验收)）；负载 30–60 时 `female-long` 从模型落地到摆上 35 s，其中要重新贴合和绑定。这时滑块和造型都不受影响。

## 导出 .blend

导出菜单的“导出 .blend”把当前身体写成绑定好的 `.blend`（内容见 [blend](blend.md)），文件名和 GLB 一致，是 `<预设>.blend`。

**接口：** `POST /api/blend` 收 `{ sex, body }`，文件好了才回答，地址在 `blend` 字段，形如 `/api/blend/<键>.blend`。`GET /api/blend` 回答 `{ blender }`，页面载入时问一次，决定菜单项能不能点；不知道时是 `null`，菜单项照常可点，点了再说。

**和命令行走同一段代码：** 工作进程的 `answer_blend` 和 `sotaigen blend` 都调 `sotaigen.generation.examined`（校验之后的求解、贴合、绑定和检查）和 `sotaigen.output.blend.write_blend`。`tests/test_editor.py` 核对两者交给 Blender 的输入（`input.json`、`input.npz`）完全相同。文件本身不要求逐字节相同，一致性比较输入和读回的结果。差别只有集合名：页面按参数取，是典型或测试身体的参数就是它的名字，否则是 `body`，这样同一个键的缓存文件对谁都对；命令行取输出文件名。两者都写完整的 `parameters`，命令行的参数文件带 `base` 时连它一起。

**单独的工作进程：** 和 IPC 导出一样，不和滑块共用，所以调滑块不会取消它。第一次导出时才启动。同时只做一个，同一个身体的请求会加入进行中的那个，不同的身体取代前一个（比如另一个打开的页面，那个页面会说被取代了）。页面离开且没有别的请求在等时取消。Blender 是工作进程的子进程，按进程组一起终止，留下的 `blend-*` 目录在下一次导出时清掉。

**缓存：** 键和 GLB 同样由 `cacheKey` 算，版本换成 `blendVersion`（生成版本加 `sotaigen-blender` 脚本，即 `blender/src/sotaigen_blender/` 的摘要，不含 `blender/review/` 这些看图和测试工具），不含 Blender 自己的版本，和构建指纹一样。放在单独的目录、单独计数，上限 8 个，按最近使用淘汰；GLB 与 `.blend` 分开计数，避免交付文件挤掉调参预览。被杀的任务留下的半成品（`.part.blend`、Blender 的 `.part.tmp.blend`、`blend-*` 输入目录）在服务启动时和下一次空闲开工时清掉。

**失败怎么说：**

| 情况 | 工作进程回答 | 页面 |
|---|---|---|
| 机器上没有 Blender | 就绪行 `blender: false`，任务回答 `noBlender` | 点之前就禁用并说明。只有点了才知道时（比如载入时没问到），状态行下面写同一句话，之后菜单项也禁用 |
| 网格损坏：翻转、越中线、皮肤不闭合 | `broken`，列出 `sotaigen.output.quality.broken` 的诊断 | “拒绝导出 .blend，网格损坏：”加逐条原因，不写文件，和 GLB 同一份判定（见[等待](#等待)）。这一步在算修正之前，所以损坏的身体很快就被拒绝 |
| 规则不通过 | `problems` | 和 GLB 一样，页面校验不通过时菜单项禁用，不发请求；只有工作进程才看得出时，写“导出 .blend 失败”和原因 |
| 求解或写文件发生异常 | `error` | 和 GLB 的生成失败一样报错，写“导出 .blend 失败”和原文 |
| 目标没到、曲面或接缝检查没过 | 照常成功 | 和 GLB 一样照常导出，问题列表里已有；这些还写进文件的 `rig["sotaigen"]["quality"]` |
| Blender 自己失败、工作进程死掉 | `error` | “导出 .blend 失败”和第一行；Blender 的长输出在运行服务的终端里。再点会启动新的 |

**耗时：** 参数文件和编辑器需要从参数求解、贴合与绑定；预设路径可读取已构建的绑定。分别测量冷启动、完整生成和缓存命中，不沿用某台机器的旧耗时。`.blend` 工作进程串行调用 `sotaigen.generation.made` 与 `Correctives.production`，和命令行共用路径。

**GPL：** `blender/` 下导入 `bpy` 的代码只由 Python 工作进程经 `sotaigen.output.blender.run_blender` 在单独的 Blender 进程里运行，不进网页、不进 `sotaigen/`。文件里不嵌 Python。

## 怎样跑

编辑器依赖本地 Node 服务与 Python 生成进程，页面不能单独托管。启动与开发命令见本页[现状](#现状)，本地访问限制见[等待](#等待)。

## 无效参数

三层校验在每次滑块事件里同步运行（`sotaigen/params/rules.py` 的第 1–3 层），第 4 层和贴合的不变量只有生成后才知道。

规则校验后还需检查生成的几何（见[参数校验](params.md#参数校验)）；无效组合比例应在当前参数范围上用压力测试重新测量。

## 流水线自己会跳

参数连续性仍需检查：沿连续参数路径逐步生成并比较顶点位移，重点查看腋下的投影是否换边。

## 参数文件

结构、字段、读文件的规则、版本和单位是对外约定，写在[参数文件](../reference/parameters.md)，金样是 `tests/contracts/parameters.json`。编辑器这一侧：

- **读文件只有一份实现：** 页面导入时把文本发给 `POST /api/params/read`，服务另起一个短的 Python（`python -m sotaigen.params.file`）读，回答读出的内容或[诊断](export.md#诊断)，所以以后的迁移只写在 Python。它不经过生成身体的工作进程，不会打断正在生成的身体。页面只写文件，格式和版本取自生成的 `params.generated.mjs`，不手抄。
- **范围外的文件** 能打开、标记无效、不夹紧，直到有人动对应的滑块；缺项不补默认值，那会悄悄换一个身体。顶层不认识的字段保留，导出时原样写回，页面提示。
- **只存规格，不存滑块值：** 头身比、身高和宏滑块都是编辑手段，把结果写进参数，文件不依赖它们。

**目标到不了时**，工作进程在 `targets` 里返回 `{参数: [目标, 实际]}`，滑块下方显示两个数，问题列表里也有一条，身体仍然生成并可导出，这一条写进文件的 `quality`。

**滑块的上下限**来自起点这份规格（预设或导入的文件），编辑过程中不变。校验按当前的长度算，所以改了躯干长之后，别的滑块上可能出现“不能生成”的区段。有的滑块会带着别的参数走：躯干长带着按躯干份额写的参数（`carriesShares`）；大腿上段围加粗时把胯厚抬到“胯对大腿太浅”要的值（`lifts`，只抬不降），因为体块在粗大腿下做不出更浅的胯。

**校验怎么共用：** `sotaigen/params/rules.py` 是唯一来源。`sotaigen_dev/editor/schema.py` 用 Python 的语法树读出规则，并写出 `sotaigen/params/spec.py` 的表和换算，生成 ES 模块。规则变了只要重跑，`pnpm run editor` 启动时会跑。只翻译纯算术，`sotaigen.params.rules` 里能读到的数值常数写成它的值，遇到不认识的写法直接报错，不猜。`tests/test_editor.py` 在 Node 下用 200 个随机身体逐条对照 Python。

**由 `sotaigen/params/rules.py` 生成 JSON Schema。发布的一份在 `sotaigen/data/params.schema.json`（`uv run sotaigen-dev schema --publish` 重写，测试核对它和生成结果一致），每个参数带单位、参照面、范围和缺省值的说明；`build/editor/params.schema.json` 是同一份。边界如下：**

| 内容 | 能否用 Schema 表达 | 现在在哪 |
|---|---|---|
| 字段、类型、必填、不允许多余的参数 | 能 | Schema，以及生成模块里的 `@typedef` |
| 每个参数的范围（第 1 层） | 能 | 同上 |
| 跨字段规则（第 2 层）和接缝规则（第 3 层） | **不能**，JSON Schema 没有算术 | 生成的模块，每条规则是一个函数 |
| 规格到内部控制量的换算 | 不能 | 同上 |
| 曲面实测（第 4 层）和不变量 | 不能，要隐式场和贴合 | 只在 Python，页面在结果回来时才知道 |
| 迁移旧版本、保留未知字段 | 不是 Schema 的事 | 读取函数 |

所以 Schema 和类型只覆盖形状，不能替代规则。用 Schema 判定“有效”比读取函数更严：范围外的文件 Schema 拒绝，读取函数仍能打开。Python 改字段时前端能发现的途径有两条：`tsc`，以及已有的测试（`sliders.json` 引用的每个参数都必须存在）。

## 五官和部件

编辑器生成和预设导出走同一份头部代码：`sotaigen.output.face.HeadShape(参数)`、`head_parts`、`blended_normals`，预设的 `face_parts`、`head_normals` 只是按预设名取参数再调用它们。绑定阶段同理共用 `sotaigen.pipeline.rig_body`。`tests/test_editor.py` 在预设上逐位核对两条路径。

## 滑块

共 61 个，定义在 `sotaigen/data/sliders.json`。分组写在 `groups` 里，左侧的顺序在 `web/editor/regions.ts`，两者都不影响结果（`applySliders` 按 `sliders` 的顺序算，`heads` 必须在它带动的项之前）。滑块的 `section` 是组内的小标题，`advanced` 收进“高级”折叠区，`measure` 在它下面放成品实测卡。

| 分组 | 调节项 |
|---|---|
| 比例 | 头高、躯干长、裆高，以及两个工具：头身比（按幂律带动 14 个参数）、身高（整体缩放） |
| 快速调整 | 丰满、体块分明（`tone`）、末端收窄（`taper`）、曲线（`curve`）。参数研究提出的宏滑块，以当前参数为零点，所以预设在动滑块之前保持原值。增益是初值，没有逐个看图定。`curve` 按躯干长的份额加大上身后靠和骨盆前倾 |
| 头部 | 头宽、头深、下颌 |
| 颈部 | 颈长、颈围 |
| 肩胸 | 肩：肩峰间距、肩峰高差、肩后移；胸廓：宽、厚；肌肉：胸肌、三角肌、斜方肌、背阔肌（毫米，加在体块上的量，缺省 0，两个性别都有；有乳房时胸肌最多 0.0225 T） |
| 胸形 | 乳房厚度场的六项：前突、基底宽、下皱襞位置、上极占比、内缘间距、最前点偏外（[胸部](../parts/chest.md#三层结构)）。后五项在前突为 0 时停用，最前点偏外缺省 0.5（居中）；在没有乳房的身体上把前突调离 0，另外四项按 `brings` 取纤细身体的比例（基底宽 0.1386 T、下皱襞 0.3027 T、上极 0.45、内缘间距 0.1951 T）作起点。男性没有这一组：当前模板一个滑块都不提供的组不进左栏，点前胸、地址里的 `panel=chest` 和换模板时停在这组都落到肩胸（`regions.ts` 的 `REGION_STAND_INS`）；性别没有的参数也不算进分组和“已改动”的计数，虽然 `breastBaseBreadth`、`breastFoldDrop` 的缺省值随躯干长变 |
| 手臂 | 上臂长、前臂长、上臂围、腕围、手长。手臂的静止角度固定为离竖直 35°，不是参数（[静止姿势](../DECISIONS.md#绑定与动作)） |
| 腰腹 | 腰：腰宽、腰腹过渡高低；侧面曲线：上身后靠、骨盆前倾（毫米，量躯干中线的错位，定义见 PARAMETERS）、腹前弧、后腰凹入，下面是腰腹实测卡 |
| 胯 | 轮廓：胯宽、胯厚、外胯高低；斜沟：斜沟深浅、邻近体块起伏（缺省是接受的造型，只能调浅） |
| 臀形 | 臀部：后突量、臀峰高低、上臀、下臀（毫米，文件缺少时显示 0）；臀下褶：长度和深浅（毫米，深浅缺省 0，调高后才能用长度移动褶线外端） |
| 腿部 | 长度：膝高（总腿长不变）；大腿：上段围度、外侧弧度，下面是胯腿实测卡；膝以下：膝围、小腿围、踝围、脚长；高级：双腿间隙、大腿前侧、脚踝高度 |

**没有直接滑块的参数：** `waistDepth`、`waistRise`、`definition`、`softness`。头身比联动会调整 `waistDepth`，`tone` 宏会调整 `definition` 和 `softness`；腰腹过渡的局部轮廓由 `waistContourShift` 调节。参数定义和量法见 [PARAMETERS](../PARAMETERS.md)。

`tests/test_editor.py` 的 `test_every_parameter_of_a_template_has_a_slider_or_a_reason` 核对每个性别的参数都有直接滑块，或属于这四项例外。

**轨道上的禁区：** `web/editor/limits.ts` 用页面本来就跑的 `validate` 提前问一遍，轨道上斜纹红色的一段不能生成，黄色的一段能生成但接缝可能有问题，悬停看原因。只标动这个滑块能改变的：不管它调到哪都不通过的规则不算它的禁区，否则整条轨道都会变红。比一个步长还窄的不标。只反映第 1–3 层，第 4 层（曲面实测，如腰胯宽可达性）和贴合的不变量要生成后才知道，所以没有标记的地方仍可能报违反不变量。`tests/test_editor.py` 在 4 组起点上对全部滑块逐段对照 Python。

**可用范围：** `pnpm run editor-sweep` 按范围内的取值在每个预设上算规则允许的部分，并在两端生成身体。可用范围由 `sotaigen/params/rules.py` 的规则和曲面检查决定，随身体和其他参数变化；应使用当前扫描结果：

| 滑块 | 情况 |
|---|---|
| `ankleHeight` | 只有一部分范围可用，因为要落在脚长的 0.24–0.55 倍之间 |
| `upperThighGirth` | 低端受限于“相对胯宽，大腿太细” |
| `chestBreadth`、`biacromialBreadth`、`acromionRise` | 受限于手臂和肋部、肩和胸廓、肩高和上臂粗的规则 |
| `chestBreadth` 低端、`chestDepth` 低端、`hipDepth` 偏高、`pelvisLean` 高端 | 胸量为 0 的身体上规则通过，但胯部前缘可能超过胸部前缘（`hipFront`）。这一项只报告，照常生成和导出 |
| `handLength` 低端 | 手接缝偏差可能超过上限（`sotaigen/form/wrap.py` 的 `SEAM_MISS_SHARE`，手 0.65） |

**界面用词：** 页面用美术口语，不搬代码里的概念。template 叫“素体”，typical body 叫“体型”，两者合起来叫“预设”；slider 叫“参数”；看的方式叫“着色”。hip 一律写“髋”，不写“胯”。分组名用“部位”两字（胸部、臀部、髋部）。解剖术语（下皱襞、上极占比、臀下褶）只写在说明里。提示句主语在前：“颈部相对头部太粗”，不写“相对头部，颈太粗”。文档里的“模板”“典型身体”是内部说法，不受这一条约束。

**提示语：** 页面拿到的都是[诊断](export.md#诊断)，按代码换成页面语言的消息，表在 `web/editor/messages.ts`，同时记下该去哪个分组调整；页面自己的范围和规则检查（`params-file.ts`）也出同样的诊断，`tests/test_editor.py` 拿它对照 Python。新增规则或代码不用同步改这个表，没收录的照代码和值显示，之后补上就行；`tests/test_editor.py` 检查页面会收到的代码都有中文。

**赛璐璐和主光：** 默认用 `toon.mjs`，可切灰模、剪影、雕塑和 X 光。主光跟随相机，和 `review` 一致，好处是环绕观察时明暗线不动。产品里要不要固定光源以后再定。相机近裁剪是 0.1 m，避免薄壳闪烁。

**判断形体用的观感（`looks.ts`）：** 地址里的 `look` 是 `silhouette`、`matcap`、`xray` 之一，也可以是 `standard`，赛璐璐不写进地址。三种都只换材质，部件开关和表情照常生效，`shot.html` 和 `review` 还没有这三种。

- **剪影：** 所有网格都用同一种深灰平涂，用来看比例、轮廓和四肢与躯干之间的空隙。
- **雕塑：** 暖色陶土 matcap，光从相机左上方来，和赛璐璐的主光同侧。看小的鼓包、凹坑和塌平的地方。贴图由代码画出，页面不加载图片。眼睛、眉毛等部件也是陶土色，看不出五官颜色。
- **X 光：** 皮肤半透明，正对相机处几乎透明，边缘不透明。骨骼画在最上层并跟随姿势：人形骨骼是橙色大点和连线，驱动用的辅助骨（`Half`、`Twist`）只画青色小点、不连线，`root` 不画。用来看关节是否落在体块里。

## 已知限制

- **机器：** 只在一台机器上测过，没有测其他 GPU 和真实网络。
- **外部 GLB：** 编辑器只显示按参数生成的身体，看别的文件用 `web/runtime/shot.html`（只有 `build/` 下的，没有控件）。
- **多个页面：** 工作进程同时只算一个身体，第二个页面的请求会取消第一个，第一个页面写“生成失败”。
- **范围边缘：** `heads` 拉到 4.0 时，有的身体因为规则差不足 0.001 被判无效，这条边界是粗扫定的。
- **下蹲悬空：** `crouch` 在页面里悬空，见[导出](export.md)（`root` 不能摆姿势）。

# 交给下游的 `.blend`

按[交给下游的绑定](../DECISIONS.md#绑定与动作)，本工具给每个身体输出绑定好的 `.blend`：控制骨给动画师转，运行时的变形骨只用约束跟随，修正形状由简单表达式驱动器驱动，控制骨上有活动范围的极限，身体上有细分曲面。转换和测试都已实现。前半说怎么用、文件里有什么、命名、关节极限；后半（[构造](#构造)起）是怎样做的和为什么这样做。

导出文件用控制骨、约束和简单驱动器重现运行时的蒙皮与姿势修正，不嵌 Python；可在禁用自动运行脚本时打开，也支持[换静止姿势](#换静止姿势)。一致性按[测试](#测试)核对，换基准后的蒙皮差异见[换基准的误差](#换基准的误差)。

**还没解决：**

- 控制骨用四元数、滚转过 90° 时以运行时还是 Blender 为准（[还没定的](#还没定的)）。
- 走路时头往前低，Q版尤其明显，观感要用户看图定（[真实动作](#真实动作)）。
- 细分后的局部收缩与接触尚未完整验证（[细分曲面](#细分曲面)）；手指的控件圆环太小、叠在一起。
- 换静止姿势后的混合蒙皮差异仍存在，前抬、滚转与触点需分别复核，见[换基准的误差](#换基准的误差)。
- 三张 IPC 接触表按摆动加扭转重新采样后缓存键失效，这里没有按新读法烘过的记录。

## 怎么运行

```sh
# 写 build/bodies/<预设>/body.blend；不写预设名就是全部预设
uv run sotaigen-dev blend female-compact
# 参数文件，和 glb 一样先做出精确的身体
uv run sotaigen blend FILE.json OUT.blend
# 要换头的细颈身体：放开“颈对头太细”这一条，见 parts/head.md
uv run sotaigen blend FILE.json OUT.blend --for-head-swap
```

编辑器的导出菜单也能导出，走同一段代码，生成完下载，见[编辑器](editor.md#导出-blend)。

- 要 Blender，查找顺序和渲染相同（`BLENDER`、`PATH`、macOS 的应用），还要 GPL 的包 `sotaigen-blender`，它带着在 Blender 里运行的脚本。缺哪个，`uv run sotaigen-dev blend` 和 `sotaigen blend` 都在计算之前说明并以 3 退出。
- 耗时需分开记录预设绑定读取、参数求解、修正、触点及 Blender 写文件；文件大小取决于本次目标数量和压缩结果。
- `body.blend` 和 `body.glb` 一样不属于构建，不进指纹；绑定重做时被删除。文件里 `generator` 的指纹可以用来核对。
- 参数文件的结果和同参数的预设逐位相同，由相同输入与文件回读检查。区别只在质量提示：参数文件没有姿势指标，不含塌陷面。
- 代码分两半。`sotaigen/output/blend.py`（Apache-2.0）读绑定的成品，写给 Blender 的输入（`input.json`、`input.npz`，交换包），再运行 `blender/src/sotaigen_blender/convert.py`。两个包分开装，版本可能错开，所以交换包带 `format`（`sotaigen/blender-bundle`）、`version` 和 `names`（读 `.blend` 的人按名字找的东西：`rig`、`body`、`headRegion`、`neckRing`、`sotaigen`，在 `sotaigen.output.blender.NAMES` 定义一次）；`convert.py` 遇到别的版本或别的名字就拒绝，什么都不写，`tests/test_blend.py` 核对 GPL 脚本里的名字和它们相同。`blender/` 下导入 `bpy` 的都是 GPL-3.0-or-later，带 SPDX 头。生产脚本是包 `sotaigen-blender`，在 `blender/src/sotaigen_blender/`：`rig.py` 是共用的部件（命名、两层骨骼、约束联动、蒙皮、修正形状的驱动器），转换和摆姿势都用它；`convert.py` 搭整个文件；`rebase.py` 换静止姿势；`pose.py` 打开文件摆姿势读回，测试用它；`head_swap.py` 是[换头](#换头)的读和写。`blender/review/` 下是看图工具（`render.py`、`head_swap_render.py`、`animate.py` 等），`blender/fixtures/made_up_head.py` 造测试头，它们不在包里。

## 换头

```sh
uv run sotaigen swap-head BODY.blend HEAD.blend OUT.blend
```

把 `BODY.blend` 的头换成 `HEAD.blend` 的，写第三个文件。头文件的约定和做法在[换头工具](../parts/head.md#换头工具)。这里说它对文件做了什么：

- `body` 还是原来的网格对象和数据块，形状键、驱动器、修改器都留着。颈以下的顶点序号不变，新头排在最后，新头的 `Basis` 就是所有修正形状的位置。表情形状键追加在修正形状之后。
- `headRegion` 改指新头的顶点，`neckRing` 不变。`rig["sotaigen"]["head"]` 按新头更新，新增 `headSwap`（模式、缩放、平移、颈口顶点数、是否焊接、融合高度、最近点比例、接缝的折角和法线）。
- 占位部件删掉（`--keep-parts` 除外）。新部件进 `parts` 集合，父级 `rig`，第一个修改器是骨架。`jaw`、眼骨和它们的控制骨移到新位置，静止旋转不变，约束不动。
- 文件照样不嵌 Python：写完用出厂设置重开，由 `pose.py` 摆检查姿势，之后才放到目标路径。

## 文件里有什么

| 东西 | 内容 |
|---|---|
| 集合 | 一个以预设名命名的集合，下有 `parts`（部件）、`mechanism`（修正的中间属性，隐藏）、`widgets`（控件形状，从视图层排除） |
| 骨架 `rig` | 变形骨沿用运行时名字，控制骨对应可写的姿势通道。骨骼集合 `controls`（子集合 `torso`、`head`、`arms`、`fingers`、`legs`）和 `deform`（隐藏）。控制骨颜色：穿着者左侧蓝、右侧红、中线黄 |
| 约束 | 变形骨的跟随、肩胛联动、前抬上抬、下颌滑动、半转与扭转分担；控制骨的关节极限。机制见[构造](#构造) |
| 驱动器 | 修正形状与中间属性使用简单表达式；每个 `jointLimit` 的开关使用平均值类型 |
| 皮肤 `body` | 模板的四边形（不切三角形，细分要四边形），UV `UVMap`，平滑着色；头部的自定义法线和 GLB 的 `head_normals` 相同，其余用 Blender 自己的。顶点组（骨的权重，加两个不是骨的：`headRegion` 是头的皮肤，`neckRing` 是颈环，给换头工具用，见[换头的接口](../parts/head.md#换头的接口)）、骨架修改器，之后是细分曲面（视口 1 级、渲染 2 级、沿用自定义法线）。材质 `skin` 和 GLB 相同 |
| 形状键 | `Basis` 加本次生成的修正形状，名字和 GLB 的 `targetNames` 相同 |
| 部件 | 10 个物体（`eyeWhite`、`iris`、`pupil`、`eyeLight`、`lash`、`brow`、`mouth`、`nose`、`ears`、`hair`），名字、材质颜色、法线和 GLB 相同；嘴绑 `head` 和 `jaw`，虹膜、瞳孔、高光绑眼骨，其余绑 `head`。表情是形状键（`blink`、`happy`、`aa`），值为 0，不驱动，给动画师直接拉。`outline`、`renderOrder` 记在材质的自定义属性上 |
| 控件 | 控制骨的自定义形状是圆环 `WGT-ring`（根骨是带前向箭头的 `WGT-root`），按骨骼周围皮肤的 90% 分位半径乘 1.2 缩放，放在骨骼中点，画在同名变形骨上（自定义形状变换），变换手柄也在变形骨上 |
| 姿势资产 | 手到头、手到脸的触点，按这个身体解好，每个一个动作（`touchCrown.left`、`.right`，可双手的还有 `.both`），标记为资产，在姿势库里。只键了手臂和手的控制骨，极限打开时不被截。够不到的触点不存，写进 `quality`（[触点](touch.md)） |
| 自定义属性 | `rig` 上：`jointLimits`（开关，默认开，可库覆盖），`sotaigen`（组：`format` 是 `"sotaigen/blend"`、`version`、`generator`、`name`、`parameters`、`correctives`（每组修正的来源）、`quality`、`head`、`restFrameError`，换静止姿势时有 `restPose`，换过头有 `headSwap`），和 GLB 的 `extras.sotaigen` 同一个函数写（[GLB 约定](export.md#glb-约定)），驱动表在文件里是约束和驱动器 |

## 命名

命名属于[冻结的骨骼与绑定约定](../reference/README.md#冻结的约定)，名字的表在 [.blend](../reference/blend.md)，金样是 `tests/contracts/blend.json`。名字在 GPL 侧 `blender/src/sotaigen_blender/rig.py` 的模块常量里定义；物体、顶点组和自定义属性的名字另在 Apache 侧 `sotaigen.output.blender.NAMES` 定义一次，随交换包带过去，两边不同就拒绝。为什么这样取名：

- **控制骨用 `_ctrl` 后缀：** Blender 的左右配对（`flip_name`，粘贴镜像姿势、X 轴镜像都用它）只认名字开头或结尾的 left/right 和 `.L`、`_L` 这类分隔。在 Blender 5.2 里实测，探针的 `CTL-leftUpperArm` 配不上对，`leftUpperArm_ctrl`、`leftUpperArmCtrl`、`leftUpperArm.ctrl` 都能。下划线让两层在大纲里一眼分开，`.` 后缀在 Blender 里常表示副本（`.001`）。变形骨保留运行时的名字。
- **约束按作用命名，小驼峰：** 和骨名、GLB 的字段同一种写法；脚本按名字找。
- **`MCH-`、`WGT-` 前缀** 沿用 Rigify 的约定：`MCH-` 表示机制，不要动；控件形状共用一个，按骨骼缩放。
- **中间属性** `<组>.<量>[.<键>]`，如 `angle.leftUpperArm.x`（摆动的转动向量 X，`.y` 扭转、`.z` 摆动的转动向量 Z，度；`.n`、`.k` 是换算的中间量）、`axilla.left.axis0.60`、`axilla.right.axis1.read`（乘了 `scale` 的读数）、`groin.gain`、`hang.left.fade1.largest`。组名就是 GLB 驱动表里组的 `name`，`axis<i>`、`fade<i>` 是组里第几根轴、第几个淡出，键值就是表里的角度。
- **集合** 以身体名命名，子集合 `parts`、`mechanism`、`widgets`；形状键和材质用 GLB 的名字，材质是 `skin` 和部件名。

## 导出分级

损坏和质量问题的判定统一见[导出分级](export.md#导出分级)，`.blend` 使用同一份 `sotaigen/output/quality.py`。拒绝时不写文件，命令行以 1 退出；原因与可行的参数调整见[哪项参数](export.md#哪项参数)。

质量报告保存在 `rig["sotaigen"]["quality"]`，与 GLB 一样区分跑过哪些检查和发现哪些问题；`.blend` 还会记录触点、换静止姿势和换头检查。参数文件不含构建时的姿势指标，不能把缺少塌陷报告理解为姿势已通过。

## 关节极限

控制骨上的旋转限制，局部空间，值来自 [range-of-motion.json](../../sotaigen/data/range-of-motion.json)，换算见 [关节的活动范围](../motion/range-of-motion.md#换到骨骼上)。分解顺序是 XYZ 欧拉，只有 `upperArm` 是 YZX（`sotaigen.rig.limits.LIMIT_ORDER`，见[上臂的分解顺序](#上臂的分解顺序)）。默认开；`rig` 的自定义属性 `jointLimits` 一键关掉，它通过每个 `jointLimit` 的“影响”上的驱动器（平均值类型，不是表达式）生效。这是唯一不在修正形状上的驱动器，是界面开关。

轴和正负号在 Blender 里摆过：每个轴转 20–30°，看肘、腕、指尖、膝、踝、脚尖往哪走，`tests/test_blend.py` 在 12 个身体的两侧都查。方向和 `range-of-motion.md` 推出的一致；脚的 Y+ 是外翻（脚底朝外）。

零点：上臂和大腿从竖直下垂量（上臂静止时侧举 35.4°、前抬 0.3°），前臂和小腿从上一节的延长线量（肘静止时屈 4.7°）。手、手指、脚不扣静止角：它们的骨骼连的是关节中心，不沿掌骨、指骨或脚底，这样量指尖会是过伸 15–22°、脚是跖屈 27°，不可信。

|---|---|---|---|
| `upperArm` | 后伸不限，前抬 170 − 0.3 | 外旋 83、内旋 60 | 收回到竖直（−35）、侧举 150 − 35 |

| `upperLeg` | 伸 18、屈 125（扣静止角，约 0.7） | 外旋 35、内旋 35 | 内收 30、外展 40 |

`upperArm` 这一行的 X、Y、Z 是按 YZX 分解读的，其余都是 XYZ。右侧镜像 Y 和 Z。没有数据的不限：肩后伸，拇指，脚趾，手指分开，胸椎的屈伸，`shoulder`、`hips`、`root`、`palmCup`。“锁住”是数据里这个关节没有这个方向的动作：肘、膝只有屈伸；前臂的旋转在这个绑定里由 `hand` 的 Y 带（扭转骨读它），所以 `lowerArm` 的 Y 锁住，会挡住把前臂旋转写在 `lowerArm` 上的动作数据。

**躯干三根骨分到哪几节：** 按骨头（转动的关节）所在的高度，以躯干长度（裆到胸骨上切迹）的比例量：`spine` 的头在 0.36，在骨盆碗里（髂嵴在 0.46），它转动上面的全部，所以是腰椎；`chest` 的头在 0.56，已在肋廓下缘（0.44）之上，代表下段胸椎（T7–L1）；`upperChest` 的头在 0.76，约在胸廓中部（胸廓中心 0.69），代表上段胸椎（T1–T7），往上到颈根（1.03，C7/T1）。胸椎的总量按 Fujimori 量的各节之和分给两段：扭转 T1–T7 共 9.5、T7–L1 共 11.9，侧屈 6.9 和 10.9。胸椎屈伸只有总弧（Morita 2014，32°），没有中立位，分不出屈和伸，`chest`、`upperChest` 的 X 不限。数据见 [range-of-motion.json](../../sotaigen/data/range-of-motion.json) 的 `thoracic`。

**检查姿势都在范围内：** 极限打开时一个检查姿势也不被截。规则是按证据补数据，不放宽极限。几处容易被截的数据和姿势的依据：

| 姿势 | 依据 |
|---|---|
| `crouch` | 脚背屈用屈膝负重的弓步测量：胫骨离竖直 38–40（Konor 2012，倾角计），极限 40。伸膝、不负重时量的 15 被腓肠肌限住，不适用 |
| `stride` | 髋伸 18，按 CDC 成人被动值（女 18.1、男 17.4） |
| `twist` | 腰椎扭转 7 有据，胸椎扭转 25（Fujimori 2012）分到两段，合计 32，所以姿势是 `spine` 7、`chest` 13、`upperChest` 10 |
| `wristRoll` | 静止时手的屈伸轴和肘轴绕前臂相差 90.8°，正是拇指朝前的中立位；手 Y 就是整个前臂的旋转，扭转骨只是分摊它。旋前 80 成立，姿势是 80 |
| `littleOpposition` | 指节的静止角从网格上量不出（各指结果互相矛盾），没找到被动过伸的来源，过伸 7 照数据，小指远节摆 −7 |

检查姿势里没有 y = 90° 的欧拉边界（`wristRoll` 在 80°，[导出](export.md#已知限制)）。逐轴欧拉限制的近似另见[关节极限](../DECISIONS.md#绑定与动作)。

### 上臂的分解顺序

上臂旋转限制使用 YZX（`Rx Rz Ry`）分解：Y 表示滚转，Z 表示手臂离开 X 摆动平面的角度，贴身下限不会随前抬变成滚转限制。数值边界来自[活动范围](../motion/range-of-motion.md)，逐轴限制仍是人体运动的近似。

腿采用 XYZ，伸髋限制作用于 X。真实动作与手动摆姿势的极限开关策略见下节。

## 真实动作

`uv run sotaigen-dev motion-blend run <预设 ...> --clip walk,wave` 把 `motions/clips/` 的片段打成控制骨的关键帧，存成 `build/motion-blend/<预设>/<片段>/motion.blend`，再重新打开读回皮肤和 `pose_verts` 对照，结果写同一目录的 `report.json`。`sheet` 出图，`film` 从文件渲染视频。这条路径不烘焙。代码是 `sotaigen_dev/motion/blend.py` 和 `blender/review/animate.py`，测试是 `tests/test_motion_blend.py`。

**动作文件关极限：** `motion.blend` 存盘时 `jointLimits` 为关，手动摆姿势的 `body.blend` 默认开。逐轴极限可能截断重定向动作，影响步幅和支撑脚；动作仍须检查几何与观感。

**先适配到控制骨**（`controls_ready`）：`sotaigen_dev/motion/clips.py` 的重定向只把骨骼方向对到源骨架上，滚转是任意的。运行时接受任何局部旋转，所以看不出来；控制骨的肘和膝是铰链、前臂旋转在手上，放不下。直接写入可能因控制骨的轴与极限产生错误姿势。适配做三件事：

- 铰链：上肢的方向不变，偏差变成绕上肢自身的扭转，下肢只剩铰链角。扭转在肢体接近伸直时定义不良，所以按帧平滑（σ = 4 帧，60 Hz）。
- 手：按掌心对齐。源的 T 姿势掌心朝下、拇指朝前，放下手臂后正好是我们的中立位。脚保持世界朝向。
- 手腕：CMU 的手有固定偏差，走路时同一个人左腕 −49°、右腕 −24°，而绑定是对称的。所以每段动作每只手减去 X、Z 的中位数，保留手势相对它的变化。这是针对这批数据的权宜做法，换有真实手腕的数据源时要去掉。

**验证边界：** `tests/test_motion_blend.py` 对照文件回读与运行时；动作适配还需分别检查肢段方向、支撑脚高度与滑动，以及超出干净范围的帧。现有少量 CMU 片段不能覆盖任意动作。

**需重点复查的现象：** 深坐的裆部锯齿折痕、深屈肘的管状轮廓、伸髋时髋前细裂纹，以及走路时头部前低。取当前动作报告的计数并看图，不能沿用旧身体的结果。

**评审工具的相机：** 带根位移的片段会走进固定相机的近裁剪面，身体被切开，看起来像破面。`sotaigen_dev/motion/blend.py sheet`（`uv run sotaigen-dev motion-blend sheet`）出图前先把身体移回取景中心；`sotaigen_dev/motion/clips.py sheet` 还没有这样做。

## 换静止姿势

按[导出时改静止姿势](../DECISIONS.md#绑定与动作)，导出 `.blend` 时可以指定另一个姿势作为文件的静止姿势，下游的衣服按别的姿势绑定时用它对齐。建模、修正、接触表、干净范围和关节极限仍然只认 A 姿势，这一步只在写文件时做。GLB 和编辑器的导出还是 A 姿势。

```sh
# 写 build/bodies/<预设>/body-rest.blend，不动 body.blend；--out 指定文件，只能配一个预设
uv run sotaigen-dev blend female-compact --t-pose
uv run sotaigen-dev blend female-compact --arm-abduction 60 --ankle-spacing 150
uv run sotaigen blend FILE.json OUT.blend --t-pose --ankle-spacing 150
```

| 参数 | 含义 |
|---|---|
| `--arm-abduction 度` | 变形上臂（肩到肘）离竖直向下的角度，在身体的额状面内，两侧相同。肩胛的分担已算在内，求的是控制骨的 (x, 0, z) |
| `--ankle-spacing 毫米` | 两个踝关节中心的距离。大腿绕 Z 外展到这个距离，脚转回原来的朝向（脚底仍是平的），根骨的子骨下移抬起的高度（脚底不离地，0.75 倍胯宽时 0.8–2.7 mm），根骨留在原点 |
| `--palms-down` | 绕手的轴转手（由前臂分担），掌心尽量朝下。A 姿势的手下垂、掌心朝内偏下，这已经是绕手的轴能转到的最朝下的地方，所以它只有和手臂抬起一起才有明显效果 |
| `--straight-arms` | 肘转到前臂最接近上臂的延长线，手的轴和上臂对齐。肘是铰链，前臂还差 2.7–3.1°（静止时的提携角） |
| `--t-pose` | 预设：`--arm-abduction 90 --palms-down --straight-arms`，即比静止的 35° 再抬约 55°。写了别的参数时以写的为准，`--no-palms-down`、`--no-straight-arms` 可以去掉，两踝不动 |
| `--past-limits` | 允许超出关节极限，见下 |

不写这些参数时，交给 Blender 的输入里没有 `restPose`，`convert.py` 不运行 `rebase.py`，文件就是 A 姿势的文件（`tests/test_rest_pose.py` 核对输入不变）。`.blend` 文件本身每次保存字节都不同，比不了字节，所以比的是输入和摆出来读回的结果。

T 姿势由 `sotaigen/rig/rest_pose.py` 按 `pose_skins` 求解。控制骨角度取每个身体的 `restPose` 报告，不把某次求解的角度范围当作固定配置。

### 范围

三档都是明确的，在进 Blender 之前判断（`sotaigen.rig.rest_pose.checks`）：

| 求出的控制骨角度 | 结果 |
|---|---|
| 在[关节极限](#关节极限)内，也在[干净范围](rig.md#关节的已知极限)内（侧举 55°、髋外展 30°、髋内收 0° 等，留 1° 余量） | 直接写 |
| 超出干净范围，没超出关节极限 | 照写，警告写进 `rig["sotaigen"]["quality"]`（`rest pose: ...`）和 `restPose.unclean`。比 A 姿势站得更窄算这一档：髋内收的干净范围是 0° |
| 超出关节极限 | 拒绝：`PastLimits`，逐条说哪个骨骼哪个轴，命令以 1 退出，不运行 Blender。加 `--past-limits` 才写，那个轴的极限放宽到包住静止姿势（否则零旋转就不是静止姿势），写进 `restPose.pastLimits` 和 `quality` |

### 骨骼：A 姿势那套原样留在里面

`blender/src/sotaigen_blender/rebase.py` 在文件搭好之后运行，读骨架，不写死骨骼名：

- 原来的变形骨和控制骨改名成机制骨（隐藏的骨骼集合 `mechanism`）：变形骨 `MCH-leftUpperArm`，控制骨 `MCH-leftUpperArm.control`。Blender 改名时带着约束的目标和驱动器的变量走，所以肩胛联动、半转骨、扭转骨、修正形状的读数和关节极限一条都不改，仍在 A 姿势的坐标系里算。
- 触点的[姿势资产](#姿势资产)跟着换算。
- 新的变形骨和控制骨用原来的名字，静止坐标系是摆好的姿势下变形骨的坐标系（控制骨和变形骨重合，层级不变）。骨骼数因此翻倍。
- 新控制骨零旋转就是新静止姿势。机制控制骨保持着静止姿势的转角（自己的 `rotation_euler`），约束 `restOffset`（复制旋转，局部空间，混合“之后”）把新控制骨的转动接在它后面，即 A 姿势下的转动是 `R · Q`。根骨和它的子骨另有 `restOffsetLocation` 传位置，其余控制骨只传旋转，缩放都不传：每多一个约束，骨链上的浮点漂移就累积一份。
- 代价：骨骼数翻倍；除根骨和它的子骨外，新控制骨只能转，不能平移，全部不能缩放。
- 新变形骨用 `followMechanism`（复制变换，世界空间）跟随机制变形骨。所以任意姿势下骨骼都到 A 姿势那个文件的位置，差的只是浮点。
- 关节极限留在机制控制骨上。新控制骨本身不被限制，超过极限时控制骨的值继续走，变形骨和圆环（画在变形骨上）停住。

文件里 `rig["sotaigen"]["restPose"]` 记着请求、`pose`（静止姿势的转角，检查姿势的写法）、`measured`（量到的角度和距离）、`aPose`（每根转过的控制骨回到 A 姿势要设的 `rotation`、`location`）和 `errorMm`。检查姿势的角度相对 A 姿势，要在新文件里摆就换算：`Q = R⁻¹ · P`（`sotaigen.rig.rest_pose.in_new_rest`）；根骨的位置减去 `pose.rootTranslation`。

### 修正形状

皮肤的 `Basis` 是摆好的皮肤。按混合蒙皮，从新静止姿势蒙皮和从 A 姿势蒙皮不是一回事：一个权重分在两根骨上（`w`、`1 − w`）的顶点 `x`，两根骨的相对转角静止姿势是 `φ`、当前比静止多转了 `Δ` 时，两者之差是

```text
w (1 − w) (I − Rot(Δ)) (Rot(φ) − I) x
```

（新静止姿势下 `Δ = 0`，差为零；只跟一根骨的顶点没有这一项。）这是矩阵混合本身的性质，任何把摆好的网格定为静止姿势的做法都有，换权重也去不掉。于是分三步：

1. **修正的 delta 随皮肤带过去：** 每个键的 delta 乘上这个顶点在静止姿势下混合矩阵的线性部分，名字和顺序不变。
2. **静止姿势下的修正烘进基础形状：** 把该姿势非零的修正写入 `Basis`，对应驱动器减去静止时的权重，允许键取负值。读数仍在 A 姿势坐标系中，转回 A 姿势时退回已烘入的量；键名和数量取本次生成的表。
3. **每根转过的控制骨一个新键 `rest.<骨名>`：** 补上面那个差。驱动器 `clamp(1 - (x * rx + y * ry + z * rz) / (r·r), -3, 3)`，读机制控制骨的 XYZ 欧拉角：静止时 0，这根骨回到 A 姿势时 1，其间和过了以后线性（上式对小的 `Δ` 正比于 `Δ`，所以外推方向是对的）。各键的形状按“逐根转回 A 姿势”逐段求差，总和正好是 A 姿势要的量。这些键排在原来的修正之后。

驱动器全是简单表达式，文件不含 Python。部件沿各自绑定骨迁移，保留自己的表情键；一致性另行回读检查。

### 换基准的误差

复现：`uv run scripts/rest_pose_study.py measure`（要 Blender）。分别生成 T 姿势及带站距的文件，在禁用自动运行脚本的新 Blender 进程里回读，与 A 姿势参考比较。

需区分两类误差：静止骨架和网格存储的浮点舍入，以及离开新旧两个静止姿势后的混合蒙皮差异。后者来自上式，集中在跨骨骼权重的顶点；`rest.*` 键只补偿构造时选定的回程，不能保证任意前抬、扭转或触点姿势与 A 姿势文件逐点相同。检查门槛见[换基准的测试](#换基准的测试)，通过数值门槛不代表观感通过。

### T 姿势的样子

`uv run scripts/rest_pose_study.py sheet <图名> --presets ...` 从文件回读网格出图。比较全身、肩腋的正面、斜前、背面与后斜方，并将 T 姿势与 A 姿势侧举结果并排。肩腋已有的长斜面和明暗折线仍需检查。

加大两踝间距通过转大腿实现，可能把大腿外侧带出胯宽测带，并改变成品最大宽度。须重新量胯宽、身高和脚底位置，不能直接沿用输入尺寸。

### 姿势资产

[触点](touch.md)的姿势资产（每个触点、每侧一个动作，存控制骨的转角 `P`）一起换算：机制控制骨做的是 `R · Q`，所以新控制骨的关键帧是 `Q = R⁻¹ · P`（`rebase.asset_pose`）。放到新静止姿势上，它键了的控制骨到 `P`，没键的（另一只手、腿）留在静止姿势。不是摆回 A 姿势，也不用摆回去。

资产回读同时检查变形骨位置和皮肤。骨骼坐标正确仍可能留下换基准的混合蒙皮差异，尤其是离新静止姿势较远的触点；需重新检查接触距离和穿插。

### 已知缺陷

- 离开新旧静止姿势后，皮肤不保证与 A 姿势文件逐点相同。
- 静止骨架的舍入会影响文件坐标和零旋转回读，二者分别设测试门槛。
- 站距变化可能扩大成品最大胯宽。
- 肘是铰链，`--straight-arms` 不能完全消除静止时的提携角。

### 换基准的测试

`tests/test_rest_pose.py` 检查 T 姿势与踝距、范围分级、参数传递、`Q = R⁻¹ · P` 和无请求时输入不变。Blender 用例还检查转回 A 姿势、零旋转、姿势资产、超限处理与文件不含 Python。

现行数值门槛：转回 A 姿势的皮肤为 0.003 mm（`SKIN_MM`）；基础坐标和新静止姿势回读为 0.006 mm（`BASIS_MM`）；其他检查姿势为 15 mm（`FAR_MM`），触点资产为 25 mm（`ASSET_FAR_MM`）。后两项用于拦截机制退化，不是接触精度或视觉验收标准。

## 控件的样子

圆环画在变形骨上，跟随联动后的肢体。手指控件可能较小、相互重叠，需在 Blender 界面检查可选性；无头模式设值不能验证操作体验。

## 构造

两层骨骼。控制骨（`<骨名>_ctrl`）是动画师转的，每根姿势里能写的骨骼一根，层级和静止坐标系和变形骨相同，不参与变形。变形骨保留运行时骨架及名字，只用约束跟随控制骨：

| 机制 | Blender 里的做法 | 结果 |
|---|---|---|
| 普通骨骼 | 复制变换约束 `followControl`，目标和自身都是局部空间 | 精确 |
| 肩胛联动（0.2） | 复制变换之后接变换约束 `shoulderRhythm`，从控制上臂的 X、Z 转角映射到 0–0.2 倍（源范围 0–180°、不外推，就是 `max(…, 0)`），混合方式“相加”，肩胛加、上臂减 | 精确 |
| 前抬上抬（0.1） | 变形肩胛和变形上臂各一个变换约束 `forwardLift`，从控制上臂的欧拉 X（源范围 0–180°、不外推）映射到自己的 Z，肩胛加、上臂减，右侧反号，混合方式“相加” | 由 `tests/test_blend.py` 对照 |
| 半转骨 | 阻尼追踪约束 `halfSwing`，目标是同一肢段变形骨的尾端，追踪 Y，影响 0.5。十根半转骨都和肢段同头、同方向、同父骨，阻尼追踪给出的正是去掉滚转的摆动，影响 0.5 按四元数插值取一半。手的半转骨在这之前先有一个 `twistShare`，读手的控制骨，取真实扭转的 0.875 | 精确 |
| 扭转骨（−0.8、−0.45、0.4、0.75） | 变换约束 `twistShare`，源旋转模式“摆动加 Y 扭转”，源 Y −180–180° 映射到 `±180° × 份额`，负份额就是反向的目标范围 | 精确 |
| 修正形状 | 形状键，值是驱动器 `a * b * g`。`a`、`b`、`g` 读一个空物体 `correctiveDrivers` 上的自定义属性：先由驱动器读出控制骨的摆动加扭转（[摆动加扭转](#摆动加扭转)）换成度，再算每个键的帐篷权重 `smoothstep(k0, k1, a) - smoothstep(k1, k2, a)`（两端只取一半）和淡出 `1 - smoothstep(0, 极限, abs(t))` | 精确 |
| `rootTranslation` | 控制根骨的位置，换到根骨自己的坐标系 | 精确 |

`smoothstep` 的差正好是 `sotaigen.corrective.drive.interval` 那种平滑的分段插值，所以帐篷函数不是近似。同一个对象上的属性驱动器串成链，一次更新就稳定（每个姿势更新两次，结果逐位相同）。更新和回读耗时需在当前环境测量。

## 误差

Blender 的坐标和计算含 32 位浮点舍入，误差会沿骨链累积。比较时使用同一权重和修正输入，分别核对静止骨架、皮肤、部件与修正权重；GLB 的量化权重另行检查，见[运行时与 NumPy 一致](export.md#运行时与-numpy-一致)。换静止姿势的结构性差异见上文，不能都归因于舍入。

## 读角度的方式

驱动器读控制骨的转角有两种变量。修正形状的驱动器和扭转骨的约束读“摆动加 Y 扭转”（[摆动加扭转](#摆动加扭转)），肩胛联动的约束读 XYZ 欧拉，都读变换通道：

- **变换通道（局部空间，XYZ 欧拉）：** 控制骨用欧拉角时，Blender 取和骨骼自己的欧拉值相容的那一组，所以滚转过 90° 也读回原值，和直接读属性逐位相同。它读的是约束之后的结果，控制骨上的旋转限制约束会生效。
- **原始属性（`rotation_euler[i]`）：** 绕过控制骨上的约束。控制骨上加了旋转限制时，复制变换的骨骼跟着被限制，读属性的肩胛联动和上臂却没有。按[关节极限](../DECISIONS.md#绑定与动作)的决定，控制骨上要有极限，所以只能用变换通道。

**控制骨用四元数时：** 运行时 `eulerFromQuaternion` 与 Blender 变换通道可能选择不同的等价欧拉分解。肩胛联动读取欧拉角，因此同一四元数未必得到相同联动；修正和扭转骨按摆动加扭转读取。复合旋转和欧拉奇异点仍需专项回读，不能用直接输入欧拉角的一致性代替。

## 摆动加扭转

修正形状按摆动加扭转读（[修正形状的读法](../DECISIONS.md#绑定与动作)），三处是同一个规则：运行时的 `sotaigen.rig.skinning.swing_twist` 和 `driver.mjs` 的 `swingTwist`，Blender 里 `blender/src/sotaigen_blender/rig.py` 的 `correctives`。

- **分解：** 旋转拆成先绕骨骼 Y 的扭转，再接一个不含 Y 分量的摆动，和 Blender 的 `quat_split_swing_and_twist` 相同（四元数先取 w ≥ 0，扭转 `2 atan2(qy, qw)`）。
- **摆动用转动向量的 X、Z：** 绕单轴转的读数就是转角，所以单轴的前抬、侧举、屈髋、扭臂和欧拉角读数逐位相同（两边都对单轴直接返回原值）。Blender 的摆动通道是摆动四元数分量的 `2 asin`，绕 (1, 0, 1) 摆 90° 读成 60°、60°；转动向量读成 63.6°、63.6°。不用通道本身做表的坐标，是因为它的定义域是 sin²(x/2) + sin²(z/2) ≤ 1 的圆，肩腋表的 (75, 110)、(95, 110) 两个角落落在外面；转动向量的定义域是半径 180° 的圆，现有的键都在里面。
- **Blender 里：** 每根被读的控制骨四个变量读通道（局部空间、约束之后，所以关节极限照样生效），五个中间属性换算：`n = sqrt(sin(x/2)² + sin(z/2)²)`（写成乘法），`k = degrees(2 asin(n) / n)`（n 极小时取 2 的度数），摆动 `k sin(x/2)`、`k sin(z/2)`，扭转 `degrees(t)`；右侧的扭转和 Z 取反。读的是上臂、大腿（两张表的键和淡出）和前臂、手（垂臂表的淡出），每侧四根。全是简单表达式。
- **精度：** 单骨分解与最终皮肤、修正权重分别对照 Python 参考；复合姿势和接近 180° 的摆动需单独覆盖。文件级门槛见[测试](#测试)。
- **表的键：** 三张表的键上的目标在不带扭转的摆动上做：肩腋 `axilla.sample_pose`、垂臂 `corrective.hang.arm_pose`（连同隐式场垂臂和胸肌随动）、接触表的 `ShoulderSampler.pose`。腹股沟的键是单轴屈髋。
- **驱动表版本：** 驱动表不另带版本，随 `extras.sotaigen.version`（[GLB 约定](export.md#glb-约定)）。

- **扭转骨也读真实扭转：** `sided` 里每根扭转骨取驱动骨摆动加扭转分解的扭转乘份额，不取欧拉 Y。上臂的两根读肩胛分担之后的上臂，前臂的两根读手。Blender 里 `twistShare` 约束的源旋转模式取“摆动加 Y 扭转”，上臂的两根读变形上臂（它们的父骨，所以没有循环），前臂的两根读手的控制骨。
- **腹股沟的淡出：** 见下面[腹股沟的淡出](#腹股沟的淡出)。

**复合姿势：** 前抬与侧举的欧拉组合包含真实扭转，例如 `(60, 0, 72)` 的扭转约 45.5°。修正按真实扭转淡出，上臂靠肩的扭转骨抵消其中 80%；单轴姿势直接读回输入角。

### 腹股沟的淡出

腹股沟的雕塑是按单纯屈髋做的，腿一扭、一侧摆就淡出。高屈髋时摆动加扭转的读数比欧拉角大：欧拉 Y 绕静止时的大腿轴转，屈髋 85° 后成了侧摆，欧拉 Z 成了扭转；坐姿 (85, 15, 12) 读成扭转 25.4、侧摆 −19.4。

扭转 120°、侧摆 80°（`sotaigen.corrective.groin.TWIST_LIMIT`、`SPREAD_LIMIT`）。依据：

- **扭转放得比侧摆宽：** 绕大腿自身的扭转几乎不挪动腹股沟的折痕，侧摆会改变折痕走向，雕塑在那里不再对。
- **验证：** 使用坐姿、跷腿、弓步、侧抬及不对称屈髋检查淡出后的轮廓与塌陷。120°／80° 是工程支持范围，不是人体生理极限，也不提供混合姿势接触保证。

## 不允许自动运行脚本时

测试在 `--factory-startup` 下打开文件，要求每个表达式驱动器的 `is_simple_expression` 和 `is_valid` 为真；关节极限开关使用平均值类型。长表达式拆为中间属性，文件不含 Python 文本块。不能用某个版本碰巧可运行的非简单表达式代替这项检查。

## 控制骨和变形骨的位置差

控制骨表达输入姿势，变形骨包含肩胛等联动结果，两者不重合。控件放在变形骨上；解手部触点时也必须量变形后的皮肤，不能只让控制链末端到位，见[触点求解](touch.md#求解)。

## 还没定的

- 控制骨用四元数、滚转过 90° 时以哪个为准：运行时的 `eulerFromQuaternion`，还是 Blender 的“离零最近”。交付的控制骨用欧拉角，测试不碰这一点。

## 没验证的

- 只在 Blender 5.2.3、一台 Mac 上做过。没有导出到 FBX 或 glTF，没有在别的软件里打开。关键帧动画只试过 CMU 的 5 段动作（[真实动作](#真实动作)），没有接过别的动作来源（比如视频动捕）。
- 换静止姿势的文件：没有在 Blender 的界面里转过控制骨（只在无头模式里设值），衣物适配尚未验证；从它导出 FBX、glTF 时 `MCH-` 骨和 `rest.*` 键怎么处理没试。
- 关键帧是欧拉角，`hips` 在 `wave` 里有接近 360° 的跳变：逐帧播放没问题，下游重采样或插值时身体可能转圈。
- 法线：修正形状的法线由 Blender 重算，没有和 GLB 的法线目标比；头部自定义法线和细分曲面一起的明暗没有逐项看。界面截图里颈根有一条亮线，和 GLB 已知的颈部明暗线台阶是不是同一个没查。
- 在 Blender 里用“粘贴翻转姿势”时左右的正负号：名字能配对（`flip_name` 实测），但翻转后的欧拉角是否就是运行时的镜像 `(x, −y, −z)` 没有摆过。
- 极限只在检查姿势和单轴转动上查过；逐轴欧拉限制在复合姿势上会不会误挡，没有系统看过。
- 控件的大小和位置只在 `female-compact` 上看过图；手指的圆环太小、叠在一起。
- 细分后的局部收缩及部件间距尚未完整验证。
- 转过 180° 附近的摆动会让阻尼追踪退化，检查姿势没到。

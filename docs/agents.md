# 给代理的约定

这里是 Claude、Codex 这类代理在本仓库工作时的约定：并行、汇报和简报。人和代理都要遵守的命令和合并规则在 [WORKFLOW](WORKFLOW.md) 和 [MERGING](MERGING.md)，外部贡献者看根目录的 [CONTRIBUTING](../CONTRIBUTING.md)。

## 并行和隔离

- **每项工作一个 worktree 和分支：** 不在主仓库目录里做多步操作。主仓库的 `build/` 是别的分支的“改前”，不要在那里试验。
- **任务的先后** 按依赖和文件冲突自己安排，不用问用户。用户说暂停，就不再派发新任务。
- **合并由主会话做，** 一次一个分支，见 [MERGING](MERGING.md#合并顺序)。

## 多个工具同时写 main

多个工具或维护者可能同时更新 `main`，合并时遵守：

- **合并前看一眼 `main`：** `git log` 里有不认识的提交，先弄清它们做了什么，保留下来。冲突时不要用自己的版本盖掉别人的。
- **失败就停：** 合并的多个步骤要连起来，一步失败后面都不跑，别在合并到一半的代码树上运行任何东西。冲突时先 `git merge --abort`，恢复主目录，再到分支里解决。
- **合并后清理：** 确认没有未提交的改动、分支已是 `main` 的祖先后，删除 worktree 和分支。值得留的实验数据先移到主仓库的 `build/`。只有未合并工作的分支才留下，改个稳定的名字，并告诉用户为什么留。不要动别的工具的分支和 worktree。
- **临时文件放自己的子目录：** 避免覆盖其他任务的文件；脚本目录不要有 `profile.py` 这类会遮蔽标准库的文件。

## 子代理工作约定

- **隔离：** 不直接提交到 `main`，由主会话汇总。
- **权限：** 不推送，不创建远端，不打标签，不公开任何内容。
- **范围：** 只做简报里的任务。范围之外的需求写进报告，不要顺手改。
- **决定：** 待用户决定的问题只提建议。新的设计取舍交给用户。
- **看图：** 见 [WORKFLOW](WORKFLOW.md#4-看图) 第 4 节。
- **诚实：** 失败和退化如实报告。不放宽测试去换通过；要改测试，必须说明它为什么错。已知缺陷写进领域文件，不用 `skip` 或 `xfail`，这两者都会让测试失败。
- **止损：** 连续多轮没有进展就停下来报告，不要硬调。
- **复用：** 优先用成熟的库，不重写通用算法；依赖管理见 [WORKFLOW](WORKFLOW.md#5-模块之间的交界)。
- **角色数据：** 不引入任何具体角色的参数、网格或肖像。
- **提交：** 一次提交一项变化，英文 Conventional Commits。文档用中文，代码注释用英文。
- **文档：** 按[内容归属和维护规则](README.md#写文档的规则)更新，不在报告之外另存探索过程。
- **数据：** `build/` 不提交；保留数据的迁移与清理见上面的“多个工具同时写 main”。报告写明实际保存位置。

## 任务交接

报告写明结论、基线与提交、验证结果、对比图、未完成或未验证的事项，以及待维护者决定的问题。改动骨骼、权重或姿势变形时，按动态解剖卡逐条说明现象是否达成，并附图。范围外的需求单独列出。

交接任务时给出基线、范围、已排除的方法和完成标准，链接到相关领域文档与动态解剖卡。人体形体的改动须注明研究依据、模型简化和验证范围。

# 参数的现实含义

每个参数是什么、单位和参照面，见由代码生成的[参数表](reference/parameters.md)（[English](en/reference/parameters.md)）；滑块的说明在 `web/messages/zh.json`（和 `en.json`）的 `slider_<name>_help`。本文解释量法、读数和现实参考；实现、范围与验证依据见[参数系统](systems/params.md)，身体的取值来源见[身体设计](systems/presets.md)。

下面的实测在隐式曲面上量，没有贴合成网格。形体改动后数字会变，复测时以这里的量法为准。

**还没解决：** 下面几个数字没有在现行身体上重量：内部倾角和两个前倾之间每度多少毫米；`estimated_controls` 的典型倍数在出厂身体上的散布；`groinDepth`、`groinRelief` 的实测峰值和标称值差多少；胸廓宽和成品胸点高度宽度之差；上臀、下臀在现行身体上的可达幅度；腹股沟造型让成品腹前弧和大腿上段围偏离隐式曲面读数多少。男性颈对头上限是否随头深变，待用户决定（[P18](DECISIONS.md#待用户决定)）。

## 结构

```text
规格（sotaigen/data/bodies/<性别>/<typical|test>/*.json、参数文件、界面）  毫米和少数无量纲比例
  │  sotaigen.form.solve.solved_controls：长度直接换算，实测目标迭代反求
  ▼
内部控制量（sotaigen/form/anatomy.py 及之后读的 p）  T 份额
```

头高、颈长、躯干长、裆高是独立输入，相加得到身高。身高和头身比是读数，界面上的同名滑块是编辑工具。工具在包里（`sotaigen/params/tools.py`），命令行是 `sotaigen scale FILE OUT [--torso 毫米] [--heads 头数] [--stature 毫米]`，页面的滑块做同样的算术：

- **头身比（`with_head_count`）：** 身高不变，按幂律改写长度和粗细，再把结果写进参数。
- **身高（`scaled`）：** 全身所有毫米数同比缩放，形状不变。
- **躯干长（`with_torso_length`）：** 以躯干长为单位的参数（`TORSO_SHARES`：大部分宽、厚、围度、四肢长、局部轮廓，以及以大腿和胯宽为单位的两项）按份额跟着走，头、颈、腿不动。范围本来就按 T 的份额定，所以单独改 T 不会再让别的参数越界。在文件里只改 `torsoLength` 时，这些参数的含义（毫米）不变，份额会变。

裆高滑块会让膝高按比例跟随，因为膝是腿的一部分。在文件里改裆高时，膝高要自己改。

可选参数不写时的值、每个参数量在什么上（参照面），都在 `sotaigen/params/spec.py` 的 `Param.default`、`Param.basis`，页面的滑块起点和包里发布的 JSON Schema（`sotaigen/data/params.schema.json`，由 `sotaigen_dev/editor/schema.py --publish` 生成，`tests/test_editor.py` 核对）都从那里来。参照面有九种（`BASES`）：骨骼地标间的长度、成品表面的实测（求解）、校准的宽度、两站连线的偏离、相对不加这一项的位移、离下面那层表面的厚度、所加形状自身的尺寸、同一部位两个尺寸之比、内部控制量（随形体版本变）。

**到不了的目标：** 范围和规则过了，目标却超出这个身体能做到的地方时，一律做到能到的地方，并报告目标和实际（`target: … asked …, reached …`），不拒绝也不改写参数。求解的围度、宽厚和姿态量，臀的上下两侧，腹前弧、后腰凹入和大腿的上段围度、外侧弧度都是这样。

规格里没有单独的 T，它就是躯干长。体块内部继续用 T 份额，因为拟合显示这些量按 T 计时几乎不随头身比变化，内部不必改。

## 命名

现有参数名和单位以[参数文件约定](reference/parameters.md)为准。命名遵循以下量法：

| 规则 | 例子 |
|---|---|
| 一段沿自己的轴的长度写 `…Length` | `neckLength`、`upperArmLength`、`lowerArmLength`、`handLength` |
| 离地的高度写 `…Height`；头高 `headHeight` 是人体测量的叫法（下巴到头顶），算例外 | `crotchHeight`、`kneeHeight`、`ankleHeight` |
| 地标在另一地标之上多少写 `…Rise`，之下多少写 `…Drop` | `acromionRise`（颈窝之上）、`waistRise`（裆之上）、`breastFoldDrop`（颈窝之下） |
| 左右写 `…Breadth`，前后写 `…Depth`，围度写 `…Girth`（ANSUR II 的词） | `biacromialBreadth`、`chestBreadth`、`hipDepth`、`neckGirth` |
| 局部轮廓以“不加这一项”为零点的位移写 `…Shift` | `glutePeakShift`、`outerHipShift`、`waistContourShift`、`thighFrontShift` |
| 无量纲的比值写 `…Ratio`；不是比值的无单位控制量不加后缀，参照面写 `control`，随形体版本变 | `headWidthRatio`、`jawBreadthRatio`、`breastApexRatio`；`headDepth`、`definition`、`softness` |
| 用骨名的词，不和骨名同名 | `lowerArmLength`（骨 `LowerArm`），不叫 `head`、`jaw` |
| 加在体块上的量写 `…Thickness` | `pectoralThickness` 等四项 |

术语：**模板**只指网格（`template/`、`sotaigen/template.py`），女性和男性共用一个。**性别**（`sex`：`female`、`male`）决定有哪些参数、范围和规则。工具自带的规格叫**身体**，分典型身体和测试身体，名字是 `<性别>-<组>`，组名（`chibi` … `rounded`、`widehip` …）不带连字符。命令行用 `--sex`、`--group` 选，参数文件的 `base.name` 记起点身体的全名。

## 量法

都在中性曲面上量，不含胸部和局部轮廓控制，定义在 `sotaigen/form/measures.py`。求解容差 0.02 mm，一个身体通常看 3–6 次曲面，约 1–2.5 秒，结果缓存在用户缓存目录的 `solve/`。

| 规格 | 量法 |
|---|---|
| `chestBreadth` | 裆上 0.71 T（现实胸点高度）的宽度，去掉手臂和腋窝凹陷 |
| `chestDepth` | 同一高度的前后距离，不含胸部 |
| `hipDepth` | 裆上 0.05、0.11、0.17 T 中最大的前后距离，去掉手臂 |
| `neckGirth` | 下巴下方 0.008 头高的水平一圈，按软尺走凸包 |
| `upperArmGirth` | 肩关节到肘 55% 处垂直于骨的一圈 |
| `wristGirth` | 腕上方 0.04 T 处垂直于骨的一圈 |
| `kneeGirth` | 膝关节处一圈 |
| `calfGirth` | 膝到踝 30%、40%、50% 处最粗的一圈 |
| `ankleGirth` | 踝上方 8%、16%、25% 处最细的一圈 |
| `upperTrunkLean` | 沿中线，裆上 0.85 T 的前后正中比 0.45 T 的前后正中靠后多少 |
| `pelvisLean` | 沿中线，裆上 0.25 T 的前后正中比 0.05 T 的前后正中靠前多少 |
| `upperThighGirth` | 裆向膝走 25% 处，单腿的水平截面一圈（`sotaigen.form.thigh.stations`），不含外侧弧 |
| `waistDepth` | 腰地标高度（`waistRise`）沿中线的前后距离，不含腹前弧和后腰凹入 |

两个姿态量读的是躯干中线的错位，由胸廓和骨盆体块的倾角实现，倾角是内部控制量。选这两个量是实测比较的结果：前后弦中点的凸度几乎看不到旋转；单量后背或小腹表面，又会被胸厚、胯厚带动，胯厚加 5% 就要让骨盆倾角变化约 6°。量中线时，胸厚的影响约为量表面时的七分之一，胯厚约为四分之一，胸廓倾角对 `pelvisLean` 几乎没有影响。两者随内部角度单调近线性。求解允许的角度是胸廓 −5–22.4°、骨盆 −5–25.2°（`sotaigen/params/spec.py` 里两项的 `bounds`），是压力扫描跑过的区间，超出时界面报告目标未达到。这些数值没有现实人群数据可比，身体动作和骨骼也都没有随之移动。

腰宽、胯宽由校准保证，准确长度（四段长度、膝高、踝高、肩峰间距、肩峰高差、臂长、手脚长）直接换算。

## 校验

范围和组合规则在生成之前校验，曲面与成品则在生成后实测。求解后分别报告目标与到达值，观感通过看图验收。规则的实现、阈值依据和复测入口见[参数系统](systems/params.md)。

## 局部轮廓的量法

这些量都以“同一身体不加这一项”为零点，单位 mm，缺项等于 0。定义和验证见[胯、臀和大腿](parts/hip-thigh.md#固定胯宽调臀形)。

| 规格 | 量法 | 是否精确 |
|---|---|---|
| `gluteProjection`、`glutePeakShift`、`outerHipShift` | 后表面、臀峰、外侧最宽处的位移 | 按坐标映射直接成立 |
| `gluteUpperFullness`、`gluteLowerFullness` | 臀峰上方 0.12 T、下方 0.10 T，距中线 0.11 T 处后轮廓的后移 | 按当前身体的后轮廓反求，到形变上限时报告实际值 |
| `gluteFoldLength` | 单侧褶线的左右跨度，两端量到深度减半 | 由形状函数解析得到 |
| `gluteFoldDepth` | 褶线最深处皮肤的前移量 | 按坐标映射直接成立，但不是看到的沟深 |
| `groinDepth` | 站姿斜沟最深处皮肤的后移量，只算沟本身 | 实测峰值接近标称值，不是看到的沟深 |
| `groinRelief` | 站姿下腹最鼓处皮肤的前移量，大腿根按固定比例跟随 | 同上 |

这两项是例外：**缺项等于已选造型，不等于 0。** 默认值是 0.027 T 和 0.014 T，也是范围上限，所以只能调轻；写 0 才是没有。这样不填的身体就是已选造型。它们只改站姿造型，屈髋动作造型不变，骨架和权重也不变；实现见[静态强度调轻](parts/groin.md#静态强度调轻)。

## 还不是成品尺寸的规格

参照面是 `control` 的那几项：`headDepth`（实际深度约为数值的 0.92 倍头高）、`definition`、`softness`、`waistContourShift`、`legClearance` 和四项 `*Thickness`。它们没有量法，同一个值做出什么随形体版本变。大腿上段围和腰厚不在其中：它们是成品上的实测量，由求解反求体块的控制量（`thighRadius`、腹部椭球的前后径），因为两者和控制量之比在出厂的 28 个身体上相差三成左右，没有常数能换算。

`tests/test_editor.py` 和 `tests/test_solve.py` 把长度和目标与地标、曲面对照，形体改动后偏离太多会失败。

## 滑块之外的规格

| 规格 | 含义 |
|---|---|
| `waistRise` | 腰地标高度，裆上多少 mm。骨骼和腰宽测量都用它 |
| `definition` | 肌肉体块的偏移和半径系数，也会增加颈部和大腿的围度 |
| `softness` | 融合半径倍率，会改变未校准的尺寸 |

## 已知的不一致

- **测量面不总是成品皮肤。** 胸廓宽不含跟随手臂的腋窝凹陷；静态腹股沟造型会改变部分网格读数。比较时先确认量的是中性场、贴合结果还是成品，见[腹股沟的测量与绑定](parts/groin.md#测量与绑定)。
- **参数变化不总是固定骨架。** `upperThighGirth` 反求体块半径，会影响髋的位置；`outerThighArc` 才是在该围度上重新分配形状。前倾量读的是表面中线，不能当作关节倾角。见[大腿控制](parts/hip-thigh.md#上胯到大腿过渡算法与两个实测控制)和上面的[量法](#量法)。
- **局部形状的可达范围因身体而异。** 上下臀由后轮廓反求，平坦后轮廓上的离散臀峰可能跳动，测量站也随之移动；当前身体到达求解边界时报告实际值，见[臀形](parts/hip-thigh.md#固定胯宽调臀形)。
- **工程控制不能当成人体尺寸。** `definition` 混合了肌肉量和分界清晰度；`legClearance` 是防互穿间隙。宏滑块的系数没有看图定过，见[风格控制](systems/params.md#风格控制)。
- **支持范围不是人群范围。** 规则内仍可能目标不可达或接缝超限；男性多数范围沿用女性，真人男性比例的覆盖仍待验证。依据和待定的头颈边界见[参数系统](systems/params.md#范围的依据与验证边界)。

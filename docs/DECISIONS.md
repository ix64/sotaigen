## 已定

### 产品与范围

- **开源和授权：** 开源；发布前完成 [WORKFLOW](WORKFLOW.md#8-发布检查) 的检查，并处理该节列出的交付缺口。未完成的验证如实列入[已知限制](reference/limitations.md)，仍待决定的验收事项由维护者确认。
  - 生成的身体（`.blend`、GLB、VRM）不加任何限制，相当于 CC0，三种下游用途都包括商用；模板也是 CC0。VRM 的授权字段默认填最宽松的选项，下游做成角色后改成自己的。
  - 数据（模板提取结果、典型身体和测试身体的规格）用 CC0。
  - 代码（Python、网页）和文档用 Apache-2.0：宽松，允许别人把生成器嵌进自己的工具或服务，比 MIT 多一条专利授权。编辑器里抄来的 shadcn/ui 组件是 MIT。
  - 用到 Blender Python 接口（`bpy`、`bmesh`）的代码用 GPL-3.0-or-later，因为 Blender 的 FAQ 说这类脚本一旦发布就要以 GNU GPL 发布，扩展平台对插件的要求也是 GPL-3.0-or-later。现在是 `template/extract.py`、`template/extract_uv.py` 和 `blender/`（`src/sotaigen_blender/` 是生成 `.blend` 的包，`review/` 是看图工具，`fixtures/` 是测试夹具）。Apache-2.0 的代码可以并入 GPLv3 的作品，所以插件可以带上生成器的代码；Python 包 `sotaigen` 只含 Apache-2.0 的代码。许可按 REUSE 规范：原文在 `LICENSES/`，根目录的 `LICENSE` 是 Apache-2.0，GPL 的文件第一行写 SPDX 头，其余按路径写在 `REUSE.toml`，`tests/test_licenses.py` 检查（见 [WORKFLOW](WORKFLOW.md#5-模块之间的交界)）。
  - 生成的 `.blend` 按 Blender 的 FAQ 是程序输出，归用户所有，不受 GPL 约束，前提是文件里不嵌 Python 脚本；交给下游的绑定只用约束和简单表达式驱动器（见[绑定与动作](#绑定与动作)），正好满足。来源：[Blender 许可](https://www.blender.org/about/license/)、[FAQ](https://www.blender.org/support/faq/)、[扩展的许可](https://docs.blender.org/manual/en/latest/advanced/extensions/licenses.html)。
  - CMU 动作数据写明“free for all uses”，继续用，按站点建议在 README 和 `LICENSES/LicenseRef-CMU-Mocap.txt` 注明出处。
- **项目名 `sotaigen`：** 素体（sotai）加 generator，表示动画风格素体生成器。商标和域名没查。
- **产品形态：** 浏览器编辑，本地生成，显示与导出使用同一份生成结果。性能目标见[架构](ARCHITECTURE.md#1-目标与边界)，生成与预览的当前方案见[编辑器](systems/editor.md)。
- **下游用途：** 绑定好的素体供角色交互、2D 姿态参考和虚拟主播使用。三类用途及要求见[架构](ARCHITECTURE.md#1-目标与边界)，各项能力的现状见领域文档。
- **模板共用：** 男女使用同一个固定拓扑模板，差别通过参数表达；模板入库并保留 CC0 来源与重新提取方法。参数和身体的组织见[按性别分组](systems/presets.md#按性别分组)，来源见[模板](../template/PROVENANCE.md)。

### 参数

- **优先使用可测量的量：** 参数文件存实际尺寸和声明过的无量纲量；身高、头身比是读数，编辑工具改写基础尺寸。内部控制量及不能视为成品尺寸的例外见[参数含义](PARAMETERS.md)。
- **目标不可达时照实报告：** 不改写用户的目标，不把身体静默挪进规则；到达值与目标分别显示。放宽范围须有相应身体的验证，现行规则与验证边界见[参数系统](systems/params.md)。
- **风格由完整规格表达：** 不设独立风格参数。典型身体按真人统计取比例，再逐组设计风格；测试身体只守独立边界，形体大改后按压力测试补充。数据来源、名字和各身体的用途统一见[身体的设计](systems/presets.md#身体的设计)。
- **胯前缘只作诊断：** 不把“胯必须在胸后面”设为不变量，孩子的小腹和年长者腹部可以靠前；量法与成品差异见[侧面的胸和小腹](systems/presets.md#侧面的胸和小腹)。

### 形体

- **腰腹与腿部先定义可测量的控制：** 腰腹过渡位置与收腰程度分开；腹前弧与后腰凹入分别控制；大腿围度与外侧弧分别表达粗细和轮廓。具体量法与实现边界见[腰腹](parts/torso.md)、[胯臀大腿](parts/hip-thigh.md)，不把某次实现方式写成永久要求。
- **胸部分层：** 胸廓、胸肌支承、乳房软组织分开，乳房采用厚度场。当前参数、依据和已知限制见[胸部](parts/chest.md)。不做明显下垂，晃动交给下游弹簧骨；需要下垂时再作为新参数设计。
- **胸围用于读数：** 胸围、下胸围、差值、腰围、臀围只显示、不输入，并报告胸围差的可达范围。角色设计中的罩杯和围度由下游按[技能指引](../skills/sotaigen/SKILL.md)换算，本工具不做拟合工具。
- **局部加密由观感决定：** 已有肘膝与肩腋环的依据见[四肢](parts/limbs.md#关节处的边环)、[肩腋](parts/shoulder-axilla.md#腋下加环)。腰腹没有显示加密的必要；手指沿长度加环不能改善截面棱角，特写使用[细分曲面](systems/blend.md#细分曲面)。拓扑变化仍受对外约定约束。

### 腹部—大腿过渡

- **先验收整体视觉，再处理技术问题：** 固定骨架，保留自然折痕，不以穿插或塌面计数排名。现象取舍以[屈髋卡](motion/pelvic-flexion.toml)为准，造型和未完成项见[腹股沟](parts/groin.md)。
- **静态造型允许调轻：** 保留已选造型为默认，`groinDepth`、`groinRelief` 只调轻静态；调轻后的观感仍待确认。量法见[参数](PARAMETERS.md#局部轮廓的量法)，实现和看图见[静态强度调轻](parts/groin.md#静态强度调轻)。

### 肩腋与胸侧

- **静态对位与动态运动分开：** 肩后移表达静止体态，动态前伸后缩表达姿势。当前肩带方案、控制项和未实现项见[肩颈对位](parts/shoulder-neck-set.md)，现象取舍见[动态卡](motion/shoulder-neck-set.toml)。
- **动作按现象取舍实现：** 肩腋、乳房随动和自然垂臂分别以[肩腋卡](motion/shoulder-chest.toml)、[垂臂卡](motion/arm-hang.toml)为准。活动范围内仍把手臂转进躯干的组合算缺陷；局部方案和验证结论归[肩腋](parts/shoulder-axilla.md)。
- **默认不烘焙或读取 IPC：** 默认生成须满足速度目标，同参数不因本机缓存不同而变化。IPC 是显式选择的实验导出路径；耗时、回退和修正来源的处理见[导出](systems/export.md#默认修正与可选接触)。
- **损坏拒绝导出，质量问题随文件报告：** 网格本身损坏不能交给下游；其他质量问题可导出，但不能隐瞒。判定和各入口行为统一见[导出分级](systems/export.md#导出分级)。

### 绑定与动作

- **交付绑定好的 `.blend`：** 下游先在 Blender 完善建模；骨骼联动用约束，修正用简单表达式，不依赖自动运行 Python。GLB 与网页驱动保留为编辑器运行时和参考实现，构造与一致性验证见[Blender 绑定](systems/blend.md)。
- **固定 A 姿势作为生成基准：** 静止姿势不是体型参数，便于复用衣物。只在导出时[换静止姿势](systems/blend.md#换静止姿势)，不改模板的生成基准，不增加站距参数；换基准的误差和限制见该节。
- **区分活动范围和干净范围：** 活动范围依据人体文献，控制骨极限默认开、可以关；不能为了动作数据放宽。干净范围是视觉质量目标，不能用无塌面代替。数值、依据与现状分别见[活动范围](motion/range-of-motion.md)、[干净范围](systems/rig.md#关节的已知极限)。
- **手到头、手到脸使用触点：** 按身体解角度，接触简化为手停在皮肤旁；触点名字、集合和手上的取点遵守[对外约定](reference/blend.md#名字)。编辑器求解、`.blend` 姿势资产、GLB 和手部 IK 的当前接入方式及原因见[触点](systems/touch.md#接入)。
- **交付质量在 Blender 中检查：** 游戏引擎还原由下游负责，不做“只有人形骨”的标准档。VRM 导出计划支持 1.0，尚未实现；近似质量底线与追踪超限表现到实现时再定。
- **VRM 使用现成插件：** 由 VRM Add-on for Blender 写文件，本工具负责导出准备，不自行实现 VRM 扩展；插件不随本工具分发。未验证事项见[VRM 差距](systems/export.md#vrm-10-差距)。
- 优化动作先按[动态解剖卡流程](motion/README.md#顺序)定现象取舍，再选技术；骨骼、权重与驱动的当前实现见[绑定](systems/rig.md)。

### 头部

- **分工：** 函数生成中性头，头颈形体与绑定按身体的标准做；五官、耳、头发只作占位，不细化。角色的脸、眼神和发型由下游制作，换头的稳定接口见[对外约定](reference/head-interface.md)，工具及局限见[头部](parts/head.md)。
- **不做视角相关变形：** 这类表现主要属于下游的脸和头发；身体保持固定形体，服务姿态参考。
- **头和身体保持连续皮肤：** `.blend` 中是同一网格，用顶点组标出头部，避免颈环法线断裂；换头时切开，完成后合回并统一法线。权重转移复用[补全方法](parts/head.md#权重转移)，衣物适配也用同一实现。
- **换头后重新检查：** 头颈配比规则保护本工具自己的头，换头应在新头上实际转头、点头检查；颈部体块自身的可达限制仍有效。当前只放行细端，粗端仍受限制，这个实现缺口见[换头工具的已知缺陷](parts/head.md#换头工具的已知缺陷)；本工具头部的粗端是否放宽见上面的待决定事项。

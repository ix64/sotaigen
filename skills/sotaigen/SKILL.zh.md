# 从角色设定做素体

本工具输出的是可绑定、可驱动的动画风格人体底模：颈下的身体、中性的头形、骨骼和权重。角色的脸、头发、衣物和具体尺寸约束都归下游。按下面的顺序做，每一步遇到的问题都记进日志（见最后一节）。现在还缺哪些能力，见[已知限制](../../docs/reference/limitations.md)；下游能依赖什么，见[对外约定](../../docs/reference/README.md)。英文版 [SKILL.md](SKILL.md) 是技能加载的那一份，也是规范文本。

## 先知道边界

| 本工具给的 | 下游自己做的 | 现在还没有的 |
|---|---|---|
| 固定拓扑的皮肤：同一模板的所有身体顶点顺序相同 | 脸、眼、眉、嘴的样式和表情 | 换头后重解手到头的姿势 |
| 由毫米实测量求出的身体，到不了的目标照实报告 | 头发和它的物理 | 衣下隐藏区域、衣物对位的地标 |
| 骨骼、权重、姿势修正，GLB 导出，`.blend` 导出时改静止姿势（手臂外展角、两踝间距、手掌朝下） | 衣物、鞋、饰品，以及它们要的额外骨骼和挂点 | 参数文件的命令行出图和摆姿势 |
| 中性的头形和头颈交界，带 `jaw` 和眼骨；五官、耳、头发只是占位 | 角色专属的尺寸和衣物约束 | VRM 导出 |

角色的参数、网格和图只放在下游自己的仓库里，不提交到本工具的仓库。

## 1. 准备

在本工具的检出目录里运行：

```sh
uv sync --all-extras
```

先安装 `pyproject.toml` 的 `required-version` 所指定的 uv；Node 推荐用 fnm 管理，读取 `.node-version`，完整步骤见 `docs/WORKFLOW.md` 第 1 节。在下游仓库里运行时加 `--project <本工具的检出目录>`，文件路径仍按当前目录算，比如 `uv run --project ../sotaigen sotaigen check 你的文件.json`。要用编辑器看图，再运行 `pnpm install`。渲染和试衣需要 Blender。本工具按这个顺序找 Blender：环境变量 `BLENDER`、`PATH` 里的 `blender`、macOS 的默认位置。求解的缓存写在用户缓存目录（macOS 的 `~/Library/Caches/sotaigen`，Linux 的 `$XDG_CACHE_HOME/sotaigen`），环境变量 `SOTAIGEN_CACHE` 可以改。

不要检出时也可以装包：`pip install sotaigen`（GLB），出 `.blend` 再装 `sotaigen-blender`，命令一样是 `sotaigen check`、`glb`、`blend`、`swap-head`、`scale`。退出码：0 完成，1 身体不行（规则、网格损坏、超关节极限），2 命令行或文件不对，3 缺 Blender（要 5.2 或更新）或 `sotaigen-blender`。Python 里是 `sotaigen.read_spec`、`generate`、`write_glb`、`write_blend`，见 `sotaigen/api.py`。

## 2. 把设定整理成实测量

规格以毫米为主，另有少数无量纲比例和角度。两个性别都有 34 项必填，另外还有可选项（乳房只有女性有），比如 `outerThighArc`、腹部和胸形的几项。

去哪里查：

- 每项怎么量：[参数表](../../docs/reference/parameters.md)、[参数的现实含义](../../docs/PARAMETERS.md#量法)，以及 `sotaigen/data/sliders.json` 里每个滑块的 `help`。
- 范围：`sotaigen/params/spec.py` 的 `ALL_SPEC`，以躯干长、头高、身高或裆高的份额表示。
- 跨项规则：`sotaigen/params/rules.py`，在 `check` 之前可以用 `sotaigen.params.rules.spec_bounds` 预先换算出毫米范围。

整理时注意：

- **身高和头身比都是读数，不是输入。** 头高、颈长、躯干长、裆高相加就是身高；穿鞋的身高要先减掉鞋底。
- **躯干长和颈长都从颈窝量起。** 躯干长是颈窝到裆，颈长是颈窝到下巴。角色设定表通常不给颈窝高度。可以从三维母版或侧视图上前中线由颈转入胸的位置读，也可以按现实比例估：颈窝在下巴下方约 0.4 头高。估出来的数会直接影响颈部规则，要标出来。
- **有几项不是成品尺寸：** `headDepth`、`definition`、`softness` 等几项是体块的控制量（见[参数](../../docs/PARAMETERS.md)）；`chestDepth`、`waistDepth` 不含胸部和腹部轮廓。设定里写的是成品尺寸时，要生成后量一次，再回头调。
- **上下胸围差现在没有直接输入，** 需要调节胸部前突、基底宽等参数，再量生成结果；可达范围随身体和参数组合变化，见[胸部](../../docs/parts/chest.md#成人身体的基底宽)。
- **先列一张表：** 每个规格项写上取值、来源（设定表上写的、从三视图读的、推断的）和误差。读图估计的数要标出来，后面出了问题先怀疑它们。

## 3. 选模板和起点

- 模板是 `female` 或 `male`，决定有哪些参数和规则。
- 典型身体在 `sotaigen/data/bodies/<性别>/typical/`，按比例和体格命名。它们的身高差别很大：

| 组 | 中文名 | 头身比（女 / 男） | 身高 mm（女 / 男） |
|---|---|---|---|
| `chibi` | Q版 | 4.0 / 4.0 | 1049 / 1058 |
| `compact` | 小巧 | 4.95 / 4.96 | 1219 / 1173 |
| `slim` | 纤细 | 6.18 / 6.25 | 1453 / 1444 |
| `long` | 修长 | 6.66 / 6.94 | 1605 / 1730 |
| `balanced` | 匀称 | 6.93 / 6.94 | 1609 / 1743 |
| `rounded` | 圆润 | 7.17 / 6.95 | 1611 / 1740 |

- 选头身比最接近的一个作起点。**不要直接照抄它的毫米值：** 先用 `sotaigen scale 起点.json 换算后.json --stature 1580`（或 `--heads`、`--torso`）换算到角色的尺度，再改你量到的项，否则没量到的项会停在起点身体的尺度上。
- 参数文件的格式见[参数文件](../../docs/reference/parameters.md)。`base.name` 写起点身体的全名，只作记录：

```json
{
  "format": "sotaigen/params",
  "version": 1,
  "sex": "female",
  "base": { "name": "female-compact" },
  "generator": "你的工具名",
  "body": { "headHeight": 0, "...": "必填项和用到的可选项" }
}
```

文件放在下游仓库里。

## 4. 校验

```sh
uv run sotaigen check 你的文件.json
```

`check` 会求解并贴合一次，通常几秒，最多几十秒。输出分两段。

**有项越过范围或违反规则时，** 只打印问题，不生成身体：

- 命令行打印的问题是英文句子，文件里存的是带代码的[诊断](../../docs/reference/diagnostics.md)。范围问题先报，范围全部通过以后才报跨项规则，所以要多改几轮。
- 范围问题直接给出毫米范围，如 `outside 176.4 to 504.7`。
- 规则问题的 `short by` 没有单位，是躯干长的份额或一个比值。下面一行 `mend one of:` 列出只改一个参数时要改多少，长度是毫米，改得最少的在前，都在范围之内。改躯干长这类长度会牵动别的份额，优先改直接相关的那一项。

**都通过以后：**

- 输出 `valid` 表示没有问题。
- `target:` 行是到不了的实测目标。
- `surface:`、`wrap:` 行是曲面和贴合的问题。
- `warning:` 行是接缝预警。
- 局部轮廓的目标（比如 `upperThighGirth`）超出当前体型能达到的范围时，报一行 `target:`，写着这个体型能达到的范围，不生成。

**遇到问题时：**

- 不要把数值悄悄挪进范围。先核对那一项的量法和来源，看是不是量错了。
- 量法没错的话，就记进日志，写清目标值、范围和依据，交给本工具的维护者决定是否放宽。
- 确实要先往下走，就挑范围内最接近的值，并在日志里写明和设定的差，以及这个差在后面哪一步造成了影响。

## 5. 生成

```sh
uv run sotaigen glb 你的文件.json 输出.glb
```

- 一具身体大约十几秒。
- 实测目标到不了时，会输出 `target:` 行，身体照样生成，但命令返回非零。把这些差记下来。
- 日常生成使用默认修正；验证接触时选择实验特性 IPC 接触表（编辑器里的 IPC 导出，或开发工具的 `--contact`）。每个新身体要烘十几到几十分钟。

## 6. 看图

现在只有编辑器能看参数文件生成的身体，并摆出检查姿势：

```sh
pnpm run editor
```

打开页面后导入参数文件，看正面、侧面、背面和各个检查姿势。`uv run sotaigen-dev review` 只认本工具自带的身体。不开编辑器的话，要自己按第 7 步驱动姿势、自己渲染。

出图与角色的三视图在同一尺度下对照比例，交给用户判断观感。

## 7. 读懂 GLB

约定写在 [GLB](../../docs/reference/glb.md) 和[坐标和拓扑](../../docs/reference/coordinates-topology.md)里。下游最常用到的几条：

- **顶点顺序：** 皮肤的前 12676 个顶点按固定顺序排列：前 8781 个是 Blender Studio 的 CC0 风格化人体模板的颈下部分，接着 3313 个是头，再后面是加的环，先是肘、膝的 400 个，再是肩、腋的 182 个，以后加的环也只往后接。UV 接缝的副本排在后面，来源记在 `extras.sotaigen.splitFrom`，所以静止顶点数等于 POSITION 数减去 `splitFrom` 的长度。按顶点序号写的东西（权重转移、衣物绑定、遮罩）可以在同一模板的所有身体之间共用。如果下游原来就用同一份 CC0 模板，前 8781 个顶点可以直接一一对应，加的环要按 `sotaigen/data/template/base-mesh.json` 的 `refined.parents` 插值。
- **骨骼的局部轴：** Y 沿骨，Z 朝前，X 是弯曲轴。
- **骨骼和修正形状要靠运行时驱动：** 辅助骨（肩胛、半转骨、扭转骨）的驱动参数在 `extras.sotaigen.drivers` 里。皮肤上还有上百个修正形状，权重由 `extras.sotaigen.correctives` 的驱动表决定（[字段](../../docs/reference/glb.md#extrassotaigen)），它们的名字不是约定，按表里列的名字找。`web/runtime/driver.mjs` 是参考实现（`poseQuaternions`、`correctiveWeights`），Node 里也能调用，输入骨骼姿势，输出全部骨骼的旋转和形态键权重。Blender 和普通播放器不读这些表，不接驱动的话，扭转、肩部、腋下、腹股沟和垂臂都会变形不对。
- **静止姿势：** 固定为 A 姿势，手臂离竖直 35°（比水平低 55°），两腿自然下垂，只留防互穿的间隙。这个角度不是参数，所有身体都一样。衣物按别的姿势绑定时（手臂外展角不同、两脚分得更开），导出 `.blend` 时指定那个姿势，它就是文件的静止姿势，衣物的权重能按骨名直接换过来，不用自己摆：`sotaigen blend 你的文件.json 输出.blend --arm-abduction 60 --ankle-spacing 150`，T 姿势写 `--t-pose`（手臂离竖直 90° 并伸直，手掌朝下），详见[换静止姿势](../../docs/systems/blend.md#换静止姿势)。GLB 仍是 A 姿势。文件里的控制骨在新静止姿势下是零旋转，修正形状照常驱动。
- **检查姿势：** 列在 `extras.sotaigen.checkPoses` 里（不是约定，可能随版本变），角度相对静止姿势，不是相对日常站姿。比如 `armsDown` 是上臂从静止姿势再往下转 24°，离竖直还有 35° − 24° = 11°。
- **五官、耳、头发：** 是皮肤之后的单独节点，嘴绑 `jaw`，虹膜、瞳孔、高光绑 `leftEye`、`rightEye`，其余绑 `head`，表情在它们各自的网格上。头的皮肤不是单独节点，它在 `body` 网格里，就是序号 8781–12093 的顶点和指向它们的 UV 副本。

## 8. 接头和头发

下游的头做好后，用 `sotaigen swap-head` 接到身体的 `.blend` 上，它只需要 Blender，不用手工切网格：

```sh
sotaigen swap-head body.blend 你的头.blend 输出.blend
```

- **换掉颈环以上的整个头：** 上面这条。它把头按颈口和头顶对齐、缩放，把颈口接到颈环上并融合一段，转移权重，把 `jaw`、眼骨移到你的头的位置，然后摆转头、点头、张嘴查塌陷。接缝不闭合或面翻转时不写文件。报告写在 `输出.json` 和文件的 `rig["sotaigen"]["headSwap"]`。
- **保留本工具的头形，只换脸和头发：** 加 `--parts-only`，部件先在这个身体的 `.blend` 上做好，位置不变。占位部件全部删掉，`--keep-parts ears` 留下点名的。

`你的头.blend` 里要有：

- 颈下开口的皮肤网格。皮肤是有开口的最大一块，或者用顶点组 `headRegion` 标出来；标了就只查这一块，没标时边界自相接触的块（生成的头发常有）跳过，留作部件。颈口的顶点数不限，头的位置由颈口中心决定，36 个顶点的颈口会逐点焊接。眼和嘴雕在头骨上开口的角色也走这条路，其他开口留着。
- 骨架里叫 `jaw`、`leftEye`、`rightEye` 的骨（或同名的空物体），放在你的头的下颌转轴和眼球中心。没有的骨留在旧位置，文件的 `quality` 里会说。
- 牙、舌、下半张脸的部件带顶点组 `jaw`，上牙带 `head`，眼球带 `leftEye`、`rightEye`，这些连通块就按组绑。没有任何骨名顶点组的（比如头发）从新皮肤转移权重，发束这样离皮肤远的会整块跟最近的地方走。皮肤上刷好的权重，离接缝远的保留。

坐标系和身体相同：X 朝穿着者左，-Y 朝前，Z 朝上，大小和物体变换随意。更多见[换头工具](../../docs/parts/head.md#换头工具)，走通的只有工具自己造的测试头，真头上遇到的问题记进日志。

注意：

- 头颈配比（颈围对头不低于 0.47）只护本工具的头，换头工具不查它，改为摆姿势检查。比这更细的颈，写身体时加 `--for-head-swap`：`sotaigen blend FILE OUT --for-head-swap`，只放开这一条，文件的质量提示里有记录，颈自己的下限仍查。完成换头后，再检查新头的转头和点头姿势。
- 工具查的是塌陷面，观感要自己看：两条路都要看转头、点头、张嘴时接缝和下巴下方的样子。手到头、手到脸的姿势资产还是按旧头解的。

## 9. 穿衣

- 衣物按身体的顶点序号做绑定和权重转移，就能复用到同一模板的其他身体上。
- 本工具没有衣物用的额外骨骼，比如袖子的蓬松骨、手上的道具挂点、包的挂点，要下游自己加。
- 衣物不会跟着修正形状动。腋下、腹股沟这些靠形态键修正的地方，衣物要自己处理。
- 双脚的间距不是规格项。`legClearance` 只是防止两腿互穿的间隙；按更宽站距做的鞋袜，导出 `.blend` 时写 `--ankle-spacing 毫米`（两个踝关节中心之间的距离）：大腿外展到这个间距，脚底保持平放、不离地，骨盆跟着下沉几毫米。
- 被衣服完全盖住的皮肤可以隐藏，但现在没有现成的隐藏区域，要自己定，并记进日志。
- 在检查姿势上看穿插，也看衣服的样子。已知会出问题的地方：肩部高侧举、腹股沟深屈髋、脚和鞋（[已知限制](../../docs/reference/limitations.md)）。

## 10. 动作检查

检查姿势见第 7 步。至少看站姿、垂臂、抬臂、下蹲、转头、点头，穿衣和不穿衣各看一遍。

## 日志

每次用都写一份，放在下游仓库，最后交给本工具的维护者。每一条写这几列：

| 列 | 写什么 |
|---|---|
| 步骤 | 上面的第几步 |
| 想做什么 | 期望的结果 |
| 实际发生了什么 | 命令、输出、截图路径 |
| 怎么绕过去的 | 没绕过去也写 |
| 归谁 | 工具缺能力、这份指引写得不对或不清楚，还是下游自己的事 |
| 影响 | 挡住了、要手工补，还是只是不顺手 |

只记事实和证据。角色的尺寸和资产留在下游日志里；向维护者报告时，用自带身体或独立构造的测试身体复现，只附不暴露角色的必要参数和步骤。
